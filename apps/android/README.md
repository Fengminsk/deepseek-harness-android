# Pocket Harness for Android

English | [中文](README.zh.md)

## Summary

This directory contains the Flutter App, a Kotlin foreground service and an embedded ARM64 Node runtime. The current artifact is a development preview for Android 9 or newer; runtime and App/Web integration still require device acceptance.

## DSH migration baseline

Pocket Harness targets the complete DSH product workflow in the App. The current preview does not yet meet that target. The original [Web bundle](../../packages/bundle/web-app/cordis.patch.yml), [standard preset](../../packages/bundle/web-app/presets/standard.patch.yml), and their owning services define the behavior to migrate; retaining their Web assets or exposing a generic API does not establish App coverage. Mobile navigation can differ, but feature semantics, Session identity, authorization, persistence and conflict behavior must remain aligned with DSH.

The [migration inventory](tool/parity-manifest.json) records the original entries and the corresponding Android code and evidence. Run `node apps/android/tool/parity-audit.mjs` from the repository root to detect unclassified source changes and invalid references. This inventory check does not execute or certify the features. Core composition, App interaction, behavior tests and device acceptance are separate evidence levels; partial implementations stay partial.

DSH already provides a [Session working-directory tree](../../packages/client/ui-sidebar-files/README.md) and [document previews](../../packages/client/ui-sidebar-documentpreview/README.md) for text, code, Markdown, images, PDF, HTML, Excel and Office documents. The current conversation menu opens Session files through the original [workspaceFiles service](../../packages/api/workspace-files/README.md), preserving the working directory, file permissions, versions and change subscriptions. Directories navigate in one native page with breadcrumbs and restored scroll positions. This is distinct from App-private files, SAF grants and Session attachment IDs; those sources retain their separate authorization.

Session documents use the original reader bundles inside a document-only Android WebView, with native floating navigation. Packaged resources and a Session-bound read bridge work with Web access disabled. Binary reads use bounded chunks; closing or cancelling the page releases requests, subscriptions and retained bytes. Local Markdown images use the same Session file service and original media size policy. Links to another document in the same Session open a reading page; returning preserves the source position. Links to a line in the current file navigate without rereading it. Cross-Session and unsupported resource links report an error. The original Office converter converted a synthetic DOCX through authorized Session reads, the Android-profile Gateway and bounded PDF transfer on the host with the packaged WASM engine. Android runs each conversion in a child Node process to release its WASM memory on exit; this does not lower the device's conversion-time memory peak. Device rendering and memory behavior remain unverified. Remote resources and interactive HTML preferences remain incomplete. Host renderer and navigation tests do not establish Android WebView acceptance.

The [Android patch](runtime/cordis.patch.yml) and [preset staging](tool/stage-preset.mjs) still omit the original terminal controller, full mobile VT renderer, sandboxed PTC workflows, and some standard tools and presets. These are migration gaps, not evidence that DSH lacks those functions. Root, device ADB control, offline model inference and boot auto-start remain outside the agreed release scope. Other platform differences require an explicit adaptation and acceptance record rather than silently dropping the original behavior.

## Build the preview

Use PowerShell 7 on Windows with Node 24, the repository's pnpm version, JDK 17, Android SDK 36, NDK 28.2.13676358, CMake 3.22.1 and Rust 1.99.1 with its `aarch64-linux-android` target. Flutter and native dependency versions are pinned in [tool/runtime-lock.json](tool/runtime-lock.json). Place the pinned Flutter checkout in the repository's ignored `.cache/flutter` directory and configure the Android SDK before continuing. Build the pinned Android ripgrep binary from a Visual Studio Developer PowerShell as described in [tool/ripgrep-android.md](tool/ripgrep-android.md).

Run the following from the repository root after `pnpm install`. The deploy command creates a new staging directory; retain that directory for subsequent App-only builds. Recreate it from a fresh deployment when the dependency lock changes. The following install restores workspace development dependencies after pnpm deploy.

```powershell
pnpm.cmd run build:artifacts
pnpm.cmd --filter dsh-python-runtime-closure deploy --legacy --prod --config.allow-unused-patches=true --config.node-linker=hoisted --config.auto-install-peers=false --config.link-workspace-packages=true --config.hoist-workspace-packages=false .cache/android/runtime-bundle
pnpm.cmd install --offline --frozen-lockfile --prod=false --ignore-scripts
./apps/android/tool/build-ripgrep.ps1 -NdkDirectory "$env:ANDROID_HOME/ndk/28.2.13676358"
node node_modules/tsx/dist/cli.mjs apps/android/tool/stage-runtime.ts
./apps/android/tool/prepare-native.ps1
node apps/android/tool/smoke-runtime.mjs
./apps/android/tool/pack-runtime.ps1
```

The native preparation script uses `http://127.0.0.1:7897` by default; supply `-Proxy` to select a different proxy. It verifies the Node archive checksum and the source revision used for the Android require-builtin addon. The staging smoke runs on the host and does not establish Android compatibility.

Run these commands from `apps/android`. The APK is written to `build/app/outputs/flutter-apk/app-debug.apk`; it uses the development signing key. Configure Gradle's HTTP/HTTPS proxy if the local network requires one.

```powershell
../../.cache/flutter/bin/flutter.bat pub get
../../.cache/flutter/bin/flutter.bat analyze --no-pub
../../.cache/flutter/bin/flutter.bat test --no-pub
../../.cache/flutter/bin/flutter.bat build apk --debug --target-platform android-arm64 --no-pub
```

Before delivery, run `tool/verify-apk.ps1` from this directory with `-ApkPath build/app/outputs/flutter-apk/app-debug.apk`, `-ExpectedVersionName` and `-ExpectedVersionCode` matching the intended build, plus `-ExpectedRuntimeSha256` from the independently packed runtime. The verifier reads the compiled Manifest and ZIP entries, requires eleven native ARM64 entries including the pinned ripgrep executable, checks its upstream license assets, and compares the embedded runtime with both its packaged and trusted SHA256. Also run `node tool/verify-document-preview.mjs build/app/outputs/flutter-apk/app-debug.apk` to check the packaged reader assets against their inventory and original module hashes. Both verifiers report JSON and exit nonzero on a mismatch. The Gradle `disable-abi-filtering` property preserves the application's explicit ARM64 filter; the APK filename does not establish its actual architectures.

## Runtime and storage

A failed or closing service instance rejects buffered runtime events and newly dispatched native work; a replacement service has an independent lifetime. Cancelling attachment selection closes a document provider's stream off the Activity thread. Cancellation does not establish that a blocked provider has stopped; the copy worker owns unpublished-file cleanup.

Replacing a ready service invalidates attachment upload receipts while retaining the selected files for explicit retry. File pages withdraw old directory actions and pagination cursors; readers can confirm the current byte position without discarding the displayed text. File-search pages preserve the query and mark old results unverified. Losing the connection does not establish that a search stopped, and reconnecting does not repeat it.

The foreground service owns one Node instance in a private Android process. Flutter uses Binder and JSON-RPC over a dedicated local socket pair; it does not use a localhost HTTP server. Standard output and error go to the private runtime log, independently of the protocol socket. Large Binder responses use read-only shared memory. The packaged runtime launches through the named `android` dsh profile and stores its workspace and sessions in app-private storage. API credentials use Android Keystore-backed encryption; authorized document trees use persisted Storage Access Framework grants.

The Runtime Status page can request a one-shot native isolation check. An Android `isolatedProcess` service receives only a bounded, read-only file descriptor and reports its UID, input digest and denied access to a separate App-private marker. Results are cleared after a service connection change. This validates the isolation foundation only; the original PTC and workflow executors remain disabled until their authorized file/tool bridge and process cancellation are implemented and device-tested.

The isolated worker also accepts an App-granted read-only regular-file descriptor for one request-scoped UTF-8 text read, limited to 64 KiB. The host verifies the returned text during the diagnostic. `node apps/android/tool/acceptance-isolated-worker.mjs` checks strict decoding, bounds and interruption on the host; Binder cancellation and UID separation still need device acceptance. This bridge does not accept paths from model output or execute JavaScript.

Android attachment, Session and ZIP publication uses a fully copied and synced temporary file followed by native `renameat2(RENAME_NOREPLACE)`. This avoids hard links denied by some devices without replacing an existing target or exposing a partial file. Original DSH hashing, collision checks, leases and append behavior remain in their owning services; other platforms retain their existing publication implementation.

Web preferences are separate from browser-editable runtime settings. The App controls the listener, scope and port; network callbacks select an explicit Wi-Fi/Ethernet IPv4 address, and an unavailable LAN address produces a waiting state. Lost service connections withdraw access links until a new observation confirms them. Late replies cannot restore an old address or erase an unsaved port. Credential rotation keeps the Agent context intact. These lifecycle paths remain subject to joint App/Web device tests.

**Web search** combines mode selection, service parameters and credential references in one native workflow. Choosing a mode updates both search and fetch routes; unrecognized combinations remain unchanged until explicitly replaced. Saving checks each original section revision, then writes parameters and credentials before routes. Sections can partially succeed and take effect immediately; the page preserves unresolved drafts and does not automatically replay unconfirmed writes.

The Android Shell tool requests approval for each command through the original DSH tool pipeline. Only `allowed-once` permits execution; rejection, cancellation and the `never` approval policy do not. Commands run with the application's existing UID and Android permissions, without a read-only or workspace-only OS sandbox. This per-command policy belongs to the Android tool and does not describe the desktop default. Root, ADB control, boot autostart and offline model inference are not implemented.

The Session resource page now opens basic Android PTYs. A separate ARM64 helper accepts raw input and resize commands; the Host retains a bounded xterm screen for reconnecting readers and closes processes on explicit request or Host disposal. The mobile page displays interpreted text, accepts complete command lines and Ctrl-C, Tab and Escape. It does not yet reproduce xterm colors, cursor interaction, arbitrary raw keyboard input or original dock behavior. The original Web terminal controller remains disabled because its `node-pty` binary is not packaged for Android. Real-device PTY and process-range acceptance remain outstanding.

Shell timeout reporting distinguishes a termination request from a delayed deadline processed after the command has ended. The deadline remains active until output pipes close, because a successfully exited shell can leave live descendants holding them open. If process observation cannot establish the result, the tool returns `timedOut: null` with `timeoutStatus: "unconfirmed"` and a diagnostic; the App explicitly displays the uncertainty. Exit code zero alone does not clear a timeout. The default timeout remains unchanged.

**Approvals and questions** and Android notifications present the same pending DSH requests as Web. Approval buttons send the existing `allowed-once` and `rejected` outcomes. Approval notifications provide notices alongside details from the actual working directory and full original Shell command, or other tools' original arguments; details exceeding 3,500 UTF-16 code units are explicitly truncated with a prompt to open the App for the complete parameters. Simple questions can use notification options or direct text replies; complex questions open the matching App page. The original question controller owns waiting, continuation and cancellation. Notification transport tokens do not grant additional permissions. Old or already answered notifications cannot reply again, and an unconfirmed submission keeps its draft without automatic replay. The App exposes system notification permission and channel settings.

**Background tasks** shows the original Agent queues, pending interaction links and recorded turn/job outcomes. Cancellation stops the current turn while preserving queued input; removing a queued item requires a separate confirmation. A successful cancellation request remains shown as stopping until the core reports idle. Missing or unverified history stays explicit. The subprocess page follows the original job catalog and byte-cursor output stream, with bounded output retention and explicit stop requests. After disconnection, it reconciles an unconfirmed stop against the reopened stream; late receipts cannot overwrite that state, and only the user can issue another stop request. Leaving either page does not cancel work.

**Subagents** lists a conversation's direct children and opens their nested catalogs and paged history in native pages. Browsing does not start or resume an Agent. Reads and controls for a session-backed child use its direct-parent and child addresses, validated by the original services. One-shot children and children whose type remains unknown have read-only history; external entries do not get fabricated session history. A continuable child can receive text through the original `queue` or `steer` operation when its parent is available. The original parent interruption operation stops the current turn and retains queued input. An unconfirmed submission keeps its draft and request identity within the current App process; refresh and reconnect only read state and never resend it automatically. This pending draft does not survive App process death. A send receipt confirms acceptance, not completed work.

**Background execution** shows the foreground service's actual task summary, CPU wake-lock state and system battery restrictions, with an entry to Android's application settings. A connection change immediately withdraws old task and wake-lock observations; late reads and setting receipts cannot confirm a replacement service. An unconfirmed setting remains visible within the current page for comparison after a fresh read and is never resent automatically. Optional CPU protection uses a bounded, renewable wake lock only while fresh core state reports active Agent work or background jobs. Waiting requests and queued input alone do not hold it; stale state releases protection and displays an unconfirmed status. Network-change callbacks are coalesced and fenced at service teardown. If the system reports a foreground-service timeout, the dedicated Agent process stops; a later launch reads interrupted records without replaying work. Android Shell now starts under a native parent-death supervisor that kills its process group if Agent dies. Android emulator fault injection covers this path, including a background descendant with closed output; ARM64 phone behavior and commands that deliberately create a new session remain unverified. These mechanisms do not guarantee survival if Android stops the process.

The optional **transparent overlay keepalive** is off by default. Enabling it requires Android's display-over-other-apps permission. The service attaches a one-physical-pixel, fully transparent, non-touchable overlay only while its current task state reports active work; completion, stale state, permission revocation and service shutdown remove it. Settings show the requested switch separately from the observed attachment state. Android may still end the process, and a fully transparent pixel does not qualify as the visible overlay required for Android 15's background foreground-service start exemption. No task or tool is replayed automatically to compensate for a process death.

A successfully completed Agent task can post one short Android notification linking to its conversation. The notice contains no reply or tool output and is suppressed while that conversation is visible. Errors, cancellation, interrupted history and reconnect do not produce a success notice. Android notification permission and system notification settings still apply.

**Automations** uses the original schedule catalog, task edits, deletion and delivery history. The App filters tasks, edits active tasks' names, prompts and timing rules, and links back to their conversations. Creation opens a conversation for the Agent's existing scheduling tools; the App does not add pause or run-now operations. Edits compare the original task record and retain the draft on conflict or an unconfirmed result. Delivery history records reminders reaching a conversation, not completed model work.

**The chat plus menu** follows DSH's Add and Commands groups and the runtime's actual command catalog. Android currently disables desktop sandbox permission presets; no substitute permission menu is fabricated. Session creation, files and non-model commands work before credentials are configured. Files use the system document picker and original session-scoped upload receipts; failed uploads retain the selected files for retry. PNG, JPEG, WebP and GIF use the original image validation, normalization and message admission through Sharp's official WASM runtime. Image sends remain subject to the selected model's input capabilities. Commands execute through the original command service. ZIP export uses the original session-log format and a system save picker.

Typing a leading `/` now searches the effective Session command catalog and skills in one inline panel. Command names and first-party localized titles use prefix-first subsequence matching; a selected command consumes the typed trigger and uses the same action as the plus menu, while a selected skill remains ordinary prompt text. A directory failure stays visible and leaves the skill rows usable. Typed lines still resolve through the original command identity and attachment rules on submission; unmatched slash text remains an ordinary message. The mobile panel does not yet implement the desktop Web menu's Arrow/Tab keyboard selection, command contribution decorations, or persistent host input chips. Its behavior has widget-test evidence but no phone acceptance.

Selected images and images referenced by the conversation open in a native zoomable viewer with retry and close controls. Historical reads use the original Session authorization; the viewer never opens an arbitrary device path. Previews have a separate 20 MiB encoded-byte limit and a bounded decode size. A failed preview does not delete the draft or change the original upload limits.

Historical file attachments open a native reader from the conversation. The original Session query authorizes the exact file reference, and the attachment store verifies its complete contents before exposing a temporary copy. UTF-8 text uses bounded pages; other formats offer the system Save As picker. Saving checks the original length and SHA256. Connection changes retain displayed text as unverified and never repeat a save; cancellation waits for copying to stop, and failures identify potentially incomplete destination files. Reading and saving neither activate an Agent nor alter the conversation.

**Conversation rendering** uses the original message source to distinguish user input from injected context. Context and system prompts remain inspectable in collapsed sections. Replies render GitHub-flavored Markdown, including tables, lists and code blocks. A lazy list builds visible conversation rows and retains disclosure state; streaming replies use their original attempt identity so retries remain distinct.

Each completed reply's More menu can create a new conversation branch at that reply's recorded `turn/end` sequence through the original `library.sessionFork` service. The child title follows the original numbered-fork convention when the source has a saved title. A confirmed branch opens after its history loads; if opening or the child-title update fails, the App reports the created session ID for retrieval from Workspaces and Sessions. Unconfirmed or partially completed forks are never automatically retried. This reply action has host-test coverage but has not been exercised on a phone.

On cold reading after an Agent process death, the App uses the original interrupted-history projection. It presents the recorded partial reply and unknown tool outcome as interrupted, without modifying the raw session log or claiming a completed tool result. Queued input is retained by the original core; the killed model turn is not resumed or replayed automatically.

**Model file tools** use the original `read`, `write` and `edit` implementations with the [filesystem sandbox provider](../../packages/fs/fs-sandbox/README.md). The Android profile defaults mutations to the workspace and permitted temporary roots; a wider retry requires the original approval for that one invocation. Overwriting or editing an existing file retains the original observed-version checks, and an edit requires a unique literal match unless `replace_all` is selected. The original `fs-sandbox` entry is disabled because `android-filesystem` subclasses that provider. Its [Android adapter](runtime/android-filesystem.mjs) publishes new files through the existing copy-and-exclusive-rename bridge instead of hard links, preserving the original version checks and approval policy. The [staged-profile smoke](tool/smoke-file-tools.mjs) exercises real host filesystem operations, rejection, cancellation and cold recovery through a synthetic local model. Android Binder and device filesystem acceptance remain unverified. This policy does not confine `android_shell` at the kernel level or restore the original `/permission` menu.

**Execution permissions** in Settings read a fresh runtime-owned policy snapshot. The screen distinguishes the original file-tool sandbox mode from Android Shell's app-UID execution and mandatory one-invocation approval, and discards observations after a runtime connection change. It exposes pending approval requests but no fictitious preset switch. The original permission-preset service remains disabled until Shell commands can be confined independently; this page does not prove device UID behavior or provide an Android equivalent of the original `/permission` command.

**Authorized files** supports single documents, folders, paged UTF-8 reads and grant revocation. SAF access remains read-only. The App and Agent share literal text search within persisted SAF grants, with optional case sensitivity and bounded reading, traversal and execution time. Results identify skipped files and incomplete searches; an empty partial result does not establish that no match exists. Cancellation waits for the native search to settle. Document authorization does not turn a `content://` URI into a Shell path.

Opening a selected PDF, image or other non-text file hands its existing SAF `content://` document URI to Android's app chooser with a temporary read grant. Plain text and source files continue to use the built-in reader, which also offers **Open in another app**. The same action for a private-workspace or Session file stages only the selected ordinary file in the App cache (maximum 256 MiB) and grants the chooser access through a non-exported `FileProvider`; it does not expose the private workspace root. Session staging reads through the original Session-scoped document service and rejects a file that changes mid-copy. Leaving the file page cancels preparation, and a separate launch handshake prevents a late chooser after navigation. This is a read-only open; edits in the other app do not write back to DSH. Staged copies are cleaned on cancellation and Activity shutdown; startup and six-hour maintenance retire files older than 24 hours or the oldest copies beyond a 512 MiB cache cap. Android may clear cache sooner. Availability of a suitable receiving app and the chooser's appearance require device validation.

Current search results open their source file within the original grant, including single-document grants. The reader checks current access and starts at the beginning; a search line number does not position the reader automatically. Returning preserves the query and results without rescanning. Unverified results after a connection change cannot open until the user searches again.

**Tool activity** pairs calls and results within their original turn and step, including nested PTC calls. Compact rows open draggable detail panels with recorded commands, separate stdout and stderr, exit codes and timeout status. Copy actions retain the complete recorded value; runtime truncation remains explicit. A panel follows its call when the row scrolls away or its group collapses, and closes when the conversation changes or the call leaves the loaded history. Consecutive calls in one known turn can be folded together without merging their records or PTC ownership. Missing results, failures and interruptions remain distinct; Agent idle does not establish a tool result. Long-pressing a message opens the FlClash popup for copying authored text or selecting a portion on a native page.

**Session models** distinguishes the current selection from an unapplied draft, with explicit selection marks and model-specific reasoning options. A blank conversation inherits the original catalog default; an unavailable saved route remains visible. The App initializes the conversation before editing, observes the original model projection, checks for changes before applying and reads back the service's normalized result. Errors retain the draft and require verification before replaying an uncertain write. The original `selectModel` API has no atomic compare-and-set operation: these checks detect observed conflicts but cannot prevent every competing write between checking and applying.

**Agent presets** has a native settings page for the original preset catalog, default selection, loading failures and read-only declarations. The new-conversation entry and session-model page open the conversation's actual preset. The preset page only reads state when opened; it does not create or resume a conversation. The original service permits selection only before the first turn; changing the default affects subsequent conversations. Default changes use the original settings revision check, and failed or unconfirmed changes retain the draft without automatic replay. Android currently ships one supported local preset; this page does not enable desktop-only capabilities.

The Android preset stages the original filesystem skill provider, skill invocation, todo and file-delivery tools without replacing their configuration. The host [portable-tools smoke](tool/smoke-preset-portable-tools.mjs) verifies discovery, invocation, parallel todo states, file-existence checks, durable events and cold reading without replay, using the Android profile and a local fixture model.

**Skills** are available through the composer menu and leading `/` suggestions. Selecting a skill inserts ordinary `/name` text; sending retains the original command precedence and skill injection. The searchable picker includes user-only skills and opens provider-supplied files in the Session reader. Preset changes, plugin operations and reconnection invalidate the directory. The [catalog smoke](tool/smoke-skill-catalog.mjs) checks cold reads without Agent activation or log writes and original user-only invocation. Sent messages highlight only skill names confirmed by their recorded injection batch. Dedicated skill rows derive their name, status and instruction text from the recorded call and result; today's catalog cannot rewrite that history. A reference opens the current provider file, while the tool row opens its recorded output. [Replay and widget tests](test/chat_skills_test.dart) cover these separate actions; their device acceptance remains pending.

**File, directory and conversation references** use the original candidate services from the composer's `@` selector. Selecting a directory inserts its reference; its separate arrow browses children. Selection preserves the original path spelling or canonical conversation mention. Query changes, page disposal and native client disconnection cancel pending discovery; connection replacement rejects old results. Sent messages use the original UTF-16 matching rules and recorded conversation labels, with file references opening the source Session reader. Folder and conversation chips remain labels, matching the original transcript behavior. The [native selector](lib/chat_references.dart), [discovery carrier](runtime/reference-discovery.mjs) and [transcript references](lib/chat_user_references.dart) have focused host regressions; phone acceptance is unverified.

**Todos and delivered files** use the original persisted events. The floating todo summary retains concurrent items, opens the recorded list and clears when a new turn starts. Completed-turn delivery cards retain exact paths, use the latest declaration for each path and open the same Session reader. Host widget tests cover restoration, updates and large-text layouts; these new controls still need device acceptance.

**Changed files** show the original completed-turn summary and open a native diff page. The App uses the same `ui-settings/enabled` preference as Web and only shows a card after the original service returns a nonempty summary. The diff compares captured turn-start and turn-end content; opening the current file is a separate action. Captured content is not durable across service restarts, so a surviving log announcement does not guarantee an available diff. Outside Git workspaces, original file-operation capture does not include arbitrary Shell modifications. [Native changes handling](lib/workspace_changes.dart), [diff regressions](test/workspace_diff_test.dart) and the [Android-profile host smoke](tool/smoke-workspace-changes.mjs) cover scoped reads, cancellation, restart limits and unchanged Session logs; Android device acceptance remains unverified.

**Subagent model selection** uses a native searchable list of exact provider/model pairs. Saved selections remain visible when a provider is unavailable. Disabling selection retains the list; enabling it requires at least one selected model. The switch and list are saved together through the original settings API with a revision check, and apply to new conversations. Conflicts retain both the current configuration and the draft for review.

**Account and configuration** pages use the original account and model services. Sign-in opens the official authorization page in an Android Custom Tab; its temporary loopback listener only serves the authorization callback and does not enable Web. The completion page's `dsh://open` link returns to the native account page without credentials or a login-state change; the original account service confirms login. Successful login invokes the original default-model initialization rules; an initialization failure preserves the signed-in account and offers a separate retry. Profile, balance and notices load independently. Model/provider credentials and defaults have native editors. Asynchronous model failures remain visible in the matching conversation after reconnecting.

Generated configuration pages retain drafts across connection changes, including invalid form or JSON input. Saves use the original redacted settings API and its revision check, preserving protected credentials. An unconfirmed write blocks another submission while read-only reconciliation checks the current values; a changed revision alone does not mean the write failed. Leaving with edits requires an explicit choice, and adopting current settings discards the draft without replaying the write.

**Plugin management** uses the original inventory, operations and receipts. The APK includes the locked pnpm and core-package archives; Android runs its Node command from the extracted native-library directory. Host tests exercise local installation and shared Cordis resolution, while device installation, lifecycle scripts and third-party compatibility still require acceptance. Package activity is counted separately from Agent turns and background jobs, including lock waits, application and rollback. Maintenance requires a synchronous reservation in the running core before saving the mode or stopping the process. Active package operations or an unknown state refuse that transition; the reservation prevents new operations until released or the process exits.

Account observations and the model directory belong to the App runtime and survive page closure within that process. Returning to the foreground reconciles the service connection and read subscriptions without replaying writes. A disconnected account remains unconfirmed while its last-read profile stays visible; a model directory marked stale must refresh before opening an editor. The original DSH credential service remains the source of authentication state; these display caches do not store another token or authorize account actions.

Foreground recovery also reconnects the Android service when the system has reclaimed its process. A bounded, shared binding handshake starts the service in its saved mode, registers a new client and reads the actual runtime status before restoring subscriptions. A connected Binder does not imply that Node is ready. Replies from the previous connection are discarded; interrupted operations are not replayed. Recovery keeps the saved Web preference and does not replace account credentials.

**Credential references** lists references declared by the current settings schemas and references entered explicitly in the App. References shared by models and tools use the original credential service. The page reads configuration status and writability, never stored secret values or account records. Replacement and removal retain their request ownership while results are uncertain; navigation and reconnect do not replay writes. Unsaved secret input survives page navigation within the current App process, not process death.

**Running settings import/export** separates choosing an operation, import input, change preview, application results and export preview. The system document picker reads or saves JSON. Included settings use readable names and grouped rows; text details open on a separate page and retain raw identifiers and revisions. Export only offers saving the file; import shows the selected changes before applying. It transfers supported ordinary settings through the original settings service. Secrets and credentials, Web controls, device authorizations, themes, plugin topology and protected Android runtime settings are excluded; this is not a complete backup. Unknown or invalid fields block import, and omitted fields keep their current values. Each namespace uses the original revision check, so several namespaces can partially succeed. The App reports each result, stops on conflict or an unconfirmed write, and retains the source for review without automatic rollback or replay. Advanced JSON editing remains available.

Replacing an import draft uses the shared confirmation dialog. Canceling the dialog or the document picker retains the draft, and repeated confirmation cannot open multiple pickers. Ordinary status and explanation text has no text-selection controls; explicit JSON views retain them.

**Diagnostics** distinguishes service startup or failure from an unconfirmed account state. Active subscription diagnostics expose only the interface name, delivery stage and received sequence; they exclude request parameters, response contents and transport identifiers. Copying or refreshing these observations does not retry business operations. The page can explicitly restart the service process; the UI waits for the actual ready event before reporting recovery. Settings reads the installed version and build number from native application metadata, with loading, failure and retry states instead of a hardcoded version label.

**Startup configuration and recovery** uses native IPC even if Node cannot start. Entering maintenance interrupts current work, waits for the previous service process to exit, and verifies remaining application processes before enabling writes. An incomplete process check leaves configuration read-only. The App edits the Android and home `cordis.patch.yml` files and the Android profile's `package.json`; the generated root configuration is not edited. Saves compare the original file hash, retain a private backup of its bytes or absence, and record an operation receipt. Restoring an absent-file backup explicitly removes the current file. Conflicts and unknown outcomes preserve drafts without automatic replay. Saving validates UTF-8, size and manifest JSON syntax; only a subsequent original DSH startup validates the complete configuration.
