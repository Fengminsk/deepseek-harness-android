# Android isolated execution admission contract

English | [中文](isolated-execution-contract.zh.md)

[`isolated-execution-contract.mjs`](../runtime/isolated-execution-contract.mjs) and its [TypeScript declarations](../runtime/isolated-execution-contract.d.mts) define an internal preflight for a future DSH PTC or workflow provider. The model-facing `ptc-runtime`, `workflow-ptc`, and `tool-workflow` entries remain disabled by the Android profile and boot guard. Calling `requireModelFacingIsolatedExecution()` fails with `ANDROID_PTC_UNAVAILABLE`. The contract does not register a tool, start a guest, approve a request, or turn the current V8 script engine into original Node PTC.

`prepareIsolatedExecution()` accepts a DSH-shaped script or workflow request and a **separate App-selected policy scope**. A model request cannot include policy, file paths for the workspace root, or a sandbox override. Its run and Session IDs must match a canonical UUID; the program and JSON args each fit the current isolated V8 64 KiB wire and the explicit deadline is at most five seconds. Workflow input retains `meta`, the JSON `args` value, and explicit total/concurrent child budgets; those fields are validated but **not executed**. The isolated guest supports bounded asynchronous broker calls, but the original workflow's `agent`, `parallel`, `pipeline` and child-agent execution are not connected.

[`workflow-child-port.mjs`](../runtime/workflow-child-port.mjs) owns an internal host-side child activation after an explicit App policy callback returns approval. That callback must verify parent ownership, schema support, narrower child scope, inherited tools and durable admission. The port caps total and concurrent child starts, keeps a published handle until disposal, suppresses dropped result rejections and disposes a child published after cancellation before rejecting its start. Its activation adapter is deliberately unbound: the current Android subagent preset can inherit App-UID Shell, and the isolated script deadline is only five seconds, so this port cannot yet launch model-requested workflow children safely. `snapshotIsolatedJson()` copies and bounds child request and result data before a future host transport, without granting effects.

The scope contains an opaque workspace ID, App-selected relative file paths or directory roots ending in `/`, exact HTTPS hosts, file and network call budgets, and lease duration. It starts with empty grants. `normalizeExecutionScope(child, parent)` refuses a new owner, Session, version or workspace and any wider path, host, budget or lease; a parent directory root can narrow to a descendant file or directory, but a similarly prefixed sibling cannot inherit it. A write root must be inside the read scope. This catches a proposed child request before native admission; the [native policy owner](isolated-execution-policy-owner.md) still owns approval, grant enforcement and durable admission. The guest receives only opaque handles for App-issued exact text files: a directory scope does not let it name arbitrary descendants. No pathname normalization in JavaScript replaces the native descriptor-anchored file broker or DNS/TLS broker.

`projectIsolatedReceipt()` requires the expected run ID and accepts only matching terminal native receipt states. `COMPLETED` requires a bounded JSON output and an observed guest UID; every cancellation, timeout, worker death and uncertain retirement withholds output. `RETIRE_UNCONFIRMED` and `INTERRUPTED_UNCONFIRMED` set `requiresReview` so callers inspect prior effects before any retry. This projection is internal and deliberately does not claim PTC `sandbox.enforcement`, Node compatibility, logs or workflow result parity.

[`isolated-execution-run.mjs`](../runtime/isolated-execution-run.mjs) adds a one-run host lifecycle around this contract. It prepares the request before any native call, admits it once through a **trusted App/Service bridge**, executes only after an admission handle echoes the expected run ID, reads a terminal native receipt and withholds even a valid result until native retirement completes. Cancellation during admission prevents guest startup; cancellation during execution or terminal reading joins the native cancellation request. A late success after cancellation, bridge exception, mismatched handle or receipt, or failed retirement cannot publish output and never triggers an automatic retry. `dispose()` waits for the same retirement. The bridge's five methods and their durable/quiescence obligations are specified in the [declaration](../runtime/isolated-execution-run.d.mts). This is a host-side contract, **not a registered tool or a working native bridge**.

The original `tool-workflow` starts a Node PTC guest with `agent`, `parallel`, `pipeline`, `phase` and `log`, foreground/background job ownership, and durable child-agent lifecycle. The Android run port covers only a bounded isolated run's admission-to-retirement sequence; it does not implement those guest hooks, the Node API surface, background jobs or safe child activation. Connecting this port to a native bridge must preserve the no-widening App policy, guest UID confinement, brokered file/network effects, and a durable terminal record before model exposure. In particular, replacing the bridge with App-UID Shell or assuming the five-second V8 guest is the original Node workflow is invalid.

Run `node --test apps/android/tool/isolated-execution-contract.test.mjs apps/android/tool/isolated-execution-run.test.mjs apps/android/tool/workflow-child-port.test.mjs` for host input, attenuation, run lifecycle, child lifecycle and terminal-result checks. Passing them does not establish Android UID isolation, Binder behavior, network routing, file-provider behavior, real approval UX or process-death recovery. The model-facing provider remains closed until the [PTC acceptance gates](ptc-execution-design.md#acceptance-gates-before-enabling-model-visible-execution) pass on a normal device.
