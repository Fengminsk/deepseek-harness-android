# PRoot 追踪进程事件候选

候选构建先验证上游归档的 SHA-256，再运行 `patch-proot-events.py`。脚本还会
核对三个被修改的上游文件，并要求每个补丁锚点恰好出现一次。原始源码归档保持
不变；归档、源码文件或锚点发生变化时，构建会拒绝继续。

启动客体前，宿主必须通过 `DSH_TRACEE_EVENT_FD` 传入编号不小于 3 的
**管道写端描述符**，并通过 `DSH_TRACEE_RUN_ID` 传入小写标准格式 UUID。
追踪器验证两者，设置 close-on-exec，移除环境变量，并在首个被追踪进程中
关闭其继承的管道描述符。缺少任一值时，候选程序拒绝运行。宿主应同时读取
管道，避免追踪器因管道写满而一直阻塞。

每条有长度上限的事件都由一次原子管道写入产生：

```
DSH_TRACE_V1<TAB>运行 UUID<TAB>传输序号<TAB>事件<TAB>第一值<TAB>第二值<LF>
```

传输序号从 1 开始，跨**所有**事件连续递增。事件包括：

| 事件 | 第一值 | 第二值 | 观察位置 |
| --- | --- | --- | --- |
| `ROOT` | 根 PID | 0 | 父进程获得首次 fork 的 PID |
| `ARM` | 根 PID | 已确认的 ptrace 选项位 | `PTRACE_SETOPTIONS` 返回成功 |
| `FORK`、`VFORK`、`CLONE` | 父 PID | 子 PID | 子进程注册完毕、重启之前 |
| `REAP` | PID | 原始最终 wait 状态 | `waitpid` 返回退出或信号终止 |
| `DRAIN` | 追踪器退出状态 | 0 | `waitpid` 返回 `ECHILD` |

宿主必须验证运行标识、帧格式、严格连续的传输序号和事件顺序。将 `ROOT`
PID 交给 `LinuxTraceeRetirementLedger` 构造器，将 `ARM` 位交给 `arm`，
再将 `FORK`／`VFORK`／`CLONE`、`REAP`、`DRAIN` 的传输序号减 2 后
送入该账本。格式错误、丢失、重复、截断或乱序事件一律判失败。
单独收到 `DRAIN` 不代表清理完成：宿主还必须确认追踪器进程结束、管道
EOF 且账本没有存活进程。写管道失败时，追踪器会以失败状态退出，不发送
`DRAIN`。取消后也不能报告成功。

这仍是**未打包、未真机测试**的候选。NDK 编译成功不能证明 Android 内核
交付了所有 ptrace 事件，亦不能证明客体所有后代进程都被回收。事件管道
不能让 PRoot 成为安全沙箱；提供文件或网络访问前，仍需 Android 隔离 UID
和能力代理。
