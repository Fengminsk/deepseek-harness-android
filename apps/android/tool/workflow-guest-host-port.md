# Android workflow guest callbacks

English | [中文](workflow-guest-host-port.zh.md)

`WorkflowGuestHostPort` is an internal callback owner for one admitted workflow. It returns bounded script inputs through `begin`, delegates `startChild`, `childResult` and `disposeChild` to `WorkflowChildPort`, and serializes `phase`, `log`, `agent-start` and `agent-end` progress to a trusted observer. It does not admit a run, execute its JavaScript, persist a Session event or expose a model tool. The App-private native workflow owner connects it to the isolated V8 guest; the model-facing workflow tool remains disabled.

The caller must supply an App-selected execution request already admitted by the durable owner, a child authorization function, a confined child activation backend, and a progress observer that durably records each accepted event before returning. `installWorkflowSubagentPreset` registers a model-only preset once per runtime; it selects native tool presentation, masks inherited tools, and denies even late child-scoped tool execution, and `createWorkflowSubagentBackend` binds each workflow to the original `spawn` activation manager. They require the exact live parent, an admitted run ID, Session persistence and query services, and one App reservation carrying the same run ID, parent ID and canonical child Session UUID for each start. A requested provider or model cannot differ from the parent route. The original schema option uses a child-local `structured_output` tool in a separate restricted preset; only its accepted structured result reaches the guest. Children have separate durable Sessions and no executable model tools. This confines model operations inside the App process; it does not provide a separate UID sandbox for the child model client. Native child callbacks require the App reservation and join activation, cancellation and retirement with the durable owner; device behavior remains unverified. Keep the preset installed while children may resume and install it again at runtime startup. The private App owner supplies durable admission and the guest caller without enabling the model-facing workflow tool. `begin` accepts one empty object and returns the validated metadata, body, JSON arguments and limits. The App-owned private workflow guest has a 120-second cap, while ordinary isolated scripts retain five seconds; this finite bound does not establish full original DSH workflow parity.

Each progress batch is copied and checked before any event is delivered. Batches contain at most 64 events and 64 KiB; one run accepts at most 2,048 events. An agent start must name a child published by this port, use an increasing sequence number, occur only once per child and have exactly one matching end. An observer failure or invalid progress immediately cancels children and prevents a clean `close()`; failed child disposal also prevents clean closure. Disposal immediately suppresses an already waiting child result, so late output cannot be published. Failed backend retirement retains its concurrency slot, stops further child starts, and cancels peer children; it cannot make room for another child whose predecessor may still be running. A child returned under an ID different from the App reservation remains owned by the port until disposal succeeds; failed disposal keeps the slot occupied and closure unconfirmed. A malformed activation with a disposable handle is retired before rejection; without a disposal handle, closure is unconfirmed and further child starts stop. Closing stops callbacks and child starts, waits for published children to retire, and emits a cancellation end for any recorded live agent. The caller must treat `ANDROID_WORKFLOW_RETIRE_UNCONFIRMED` as an uncertain outcome and must not publish a successful workflow result.

Host checks: `node --import tsx --test apps/android/tool/workflow-child-port.test.mjs apps/android/tool/workflow-guest-host-port.test.mjs` and `node --import tsx --test apps/android/tool/workflow-subagent-backend.test.mjs`. The integration test exercises the real child Agent and Session lineage, tool execution denial, exact child identity, model-route narrowing, App refusal, result/disposal and same-process cold resume with a scripted model. Process-restart recovery, native child-ledger integration, device execution, original `parallel`/`pipeline` behavior, durable workflow progress and model-facing PTC remain unverified or unavailable.
