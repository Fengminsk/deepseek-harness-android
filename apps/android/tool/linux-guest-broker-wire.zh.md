# 原生 Linux 客体代理帧

[English](linux-guest-broker-wire.md) | 中文

`LinuxGuestBrokerWire` 准入未来隔离客体传来的完整帧。调用方须提供 Binder 实际观察到的发送 UID。协议核对 UID、任务 ID、有效策略租约、操作范围、重复调用 ID 和调用额度。本代码不启动客体，也不发放文件描述符、App 路径或套接字；尚未启用模型工具。

## 版本 2 请求

固定 82 字节帧头依次为 `DSHB`（4）、版本 `2`（1）、操作码（1）、零保留位（2）、规范 ASCII 任务 UUID（36）、规范 ASCII 调用 UUID（36）和大端无符号负载长度（2）。负载须恰为 1–2048 字节。版本 1、尾随数据和非法 UTF-8 都会被拒绝。文件路径必须是 `/workspace/` 下的虚拟精确文件名；可变字符串之前有大端无符号 16 位 UTF-8 字节长度。

| 操作码 | 负载 |
| --- | --- |
| 1 读取 | 路径、预期版本、非负有符号 32 位字节偏移、无符号 16 位最大块长（1–3800） |
| 2 搜索 | 路径、字面量查询词、无符号 16 位最大匹配数（1–256） |
| 3 编辑 | 路径、预期版本、字面量待替换文本、替换文本（可为空）、无符号 16 位最大替换数（1–4096） |
| 4 HTTPS | 一个严格 ASCII `https://` 完整 URL，含路径和查询，负载内部不再有字符串长度字段 |

首次读取或新文件编辑可用 `missing` 作为预期版本，其他情况用 64 位小写 SHA-256。偏移大于零的读取必须带版本。分页期间文件变化会返回已审计的 `STALE` 拒绝，避免拼接不同版本的数据。搜索和编辑沿用现有有界文本校验。HTTPS 准入校验完整 URL 和精确标准化主机；HTTPS 代理仍须自行检查 DNS、重定向、TLS 和策略。

## App 侧文件分发与回复

`LinuxGuestFileBrokerDispatch` 仅接收属于当前协议实例的待处理请求。它把允许的虚拟文件映射为 `IsolatedCapabilityBroker` 持有的一条精确授权；不把授权句柄和 App 路径传给客体。代理通过传入的 `WorkspaceOps` 执行锚定操作，通过 `AuditSink` 持久记录任务、授权、调用和终态；取消条件持续检查 Linux 租约。只有持久结算并写入终态后才调用 `wire.complete`。审计失败、编辑提交结果不明、租约过期或撤销都会取消任务，不发送成功回复。

读取成功负载为一字节版本长度、ASCII 版本、无符号 32 位 UTF-8 总字节数、无符号 32 位请求偏移、无符号 16 位块长度、原始块字节。块边界可能落在 UTF-8 字符中，调用方必须按同一版本拼好字节后再解码。搜索成功负载为版本、无符号 16 位命中数、一字节截断标志，然后每个命中包含无符号 32 位行号和列号、无符号 16 位 UTF-8 摘要长度和摘要。编辑成功负载为带一字节长度的旧、新版本，以及无符号 32 位结果字节数。回复操作码 `0x81`、`0x82` 分别是已审计的成功与拒绝，负载最多 4096 字节。拒绝负载目前只含 `STALE` 等简短 ASCII 状态。

正式调用方须传入锚定于 App 私有工作区的 `IsolatedCapabilityWorkspace` 与持久化的 `IsolatedCapabilityJournal`。分发类只是能力接线点，尚无运行中的原生客体；未来仍需隔离传输、PRoot 证据、终态日志桥接和工具注册。运行 `node apps/android/tool/acceptance-linux-guest-broker-wire.mjs` 可执行主机协议与文件代理检查；真机行为未验证。
