# Isolated script run controller

English | [中文](isolated-script-run.zh.md)

[`IsolatedScriptRunController`](../android/app/src/main/kotlin/com/minnnng/dsh_android/IsolatedScriptRunController.kt) accepts one App-owned run ID, a bounded JavaScript function expression, JSON input, a 1–5000 ms execution limit, and a cancellation source. It is internal infrastructure with no production caller: Android's DSH `run_code` and workflow profile entries remain disabled, and the model cannot invoke this path. A pure run exposes no host object; an explicitly leased App-owned policy may add bounded file or HTTPS host calls. The guest itself exposes no Node APIs, ambient file or network APIs, timers or host-call promises. This remains short of DSH PTC parity.

The App writes an `ADMITTED` receipt in its private `files/isolated-script-runs` directory and syncs the file and directory before binding. On Android 10+, `bindIsolatedService` gives each run a named isolated service instance. Android 9 refuses the controller because it cannot supply the same per-run binding property. [`IsolatedScriptWire`](../android/app/src/main/java/com/minnnng/dsh_android/IsolatedScriptWire.java) fixes protocol version 1, canonical UUID run ID and nonce, exact Binder fields, script/input/output byte limits, and one result. The App verifies Binder's sender UID, requires it to differ from the App UID, and corroborates the guest's reported UID. No path, credential, or permission grant crosses this protocol.

The guest runs [`PtcScriptEngine`](../android/app/src/main/java/com/minnnng/dsh_android/PtcScriptEngine.java) on its own worker thread. It reports a bounded result, then waits for the App's `RETIRE` message and exits. The App accepts `COMPLETED` only after the bound Binder has died, `unbindService` has returned, and a terminal receipt has been atomically replaced and directory-synced. Cancellation, total-deadline expiry, malformed Binder values, and premature guest death never publish a successful output. If guest death or binding cleanup cannot be confirmed by the deadline, the receipt says `RETIRE_UNCONFIRMED`; it is not a safe completion. A guest also links to the App reply Binder and terminates if the App process dies.

[`IsolatedScriptReceipt`](../android/app/src/main/java/com/minnnng/dsh_android/IsolatedScriptReceipt.java) refuses a reused run ID. The controller accepts calls only in the `:agent` process and serializes startup recovery and durable admission there; separate admitted runs may then bind and execute concurrently. Its first run after that process starts reconciles previously admitted receipts as `INTERRUPTED_UNCONFIRMED` without replay. A damaged receipt remains in place and refuses replay, but does not block recovery of unrelated runs; a directory sync failure during recovery still aborts new work. Reconciliation cannot establish the exact outcome of a killed App process. The controller has no public caller or cross-process scheduler. A dedicated callback thread handles each run's Binder messages and service binding so a busy main thread cannot delay guest retirement. No Android device has yet executed this JNI path, so isolated UID assignment, Binder timing, native loading, kill/cancel, parallel binding and process-death behavior remain unverified on device.

The App records each canonical UUID in one of 256 append-only, checksummed ID buckets and syncs that record before creating the bindable receipt. A missing migration marker triggers import of existing receipt names into the ledger; the marker is atomically replaced and directory-synced only after the import. A damaged marker refuses startup. The single-writer store discards unpublished replacement temps and syncs the directory before quota inspection or recovery; the original receipt and admitted ID remain. Normal admission reserves one replacement slot among the 1,024 receipt-file limit, with a separate 128 MiB full-receipt budget. When admission needs space, only terminal receipts with confirmed ledger IDs are removed, oldest first. Their result text is no longer readable from this store, but their IDs remain refused. Active, damaged, or unverifiable receipts are never pruned. A damaged ledger bucket rejects new IDs in that bucket without making other buckets writable for its IDs.

The ID ledger has a separate 128 MiB limit, including bucket headers. Exhaustion refuses new admission with `CapacityExceededException`; a torn or damaged bucket refuses admission in that bucket. No admitted ID is deleted or reset. Because arbitrary UUIDs require persistent identity history, this still has a finite lifetime capacity, now millions of admissions rather than 1,024. Directory or file sync failure never permits binding; an uncertain ID may be permanently consumed. The host checks cover legacy migration, compaction, replay refusal, torn buckets and quota. Device filesystem durability and process-death behavior remain unverified.

Host checks: `node apps/android/tool/acceptance-isolated-script-run.mjs` verifies wire bounds, terminal classification and durable no-replay receipt transitions. `:app:compileDebugKotlin :app:compileDebugJavaWithJavac` verifies Android linkage. These do not replace a normal non-rooted device run, followed by negative tests for infinite loops, memory pressure, cancellation, malformed messages, Binder death and App process death.
