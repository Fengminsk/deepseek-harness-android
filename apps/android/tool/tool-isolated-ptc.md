# Android model PTC entry

English | [中文](tool-isolated-ptc.zh.md)

The Android `android_ptc` tool runs one reviewed TypeScript async-function body with top-level `await` and `return`. The model supplies only `code` and `description`. This is separate from the original DSH `run_code` transport and unrestricted Node PTC provider: direct Node APIs, imports, App-UID shell, filesystem and network access remain unavailable inside the guest.

The runtime composes the [App-owned PTC owner](model-ptc-readonly.md) with the native isolated-execution bridge, durable callback journal and original Agent/ToolRuntime services. `MODEL_PTC_DEVICE_ACCEPTED=true` enables its model registration in source. This switch is not a model argument, profile setting or remote value. Original `ptc-runtime`, `workflow-ptc` and `tool-workflow` plugins remain protected and disabled; the separate reviewed native workflow registration is source-enabled for the Build 116 candidate, with its workflow-enabled production profile still pending end-to-end verification.

The owner captures the actual active ToolRunContext, Agent, Session and exact first-party tool registrations. The [reviewed callback table](model-ptc-readonly.md#reviewed-calls) covers current-session files and attachments, workspace mutations under live policy, configured web providers, direct-child queries and the parent's four Linux tools when present. Every nested call rechecks its registration and policy through the original ToolRuntime. The guest receives zero direct native file or network grants. Copied definitions, lost parent execution, recursive delegation and arbitrary tool names are rejected.

The unchanged limits are 32 callbacks, 120 seconds elapsed including callback waits, and 5 seconds of execution-thread CPU. Linux boot and execution waits consume that shared wall deadline; serial steps must fit within it. Cancellation and uncertain retirement withhold the program value while durable callback and publication facts remain available. Scope teardown cancels and joins active runs. These limits and the disabled direct-Node environment are not full upstream PTC parity.

Installed Build 115 r15 exercised real AgentLoop/ToolRuntime calls, file/web/attachment/APK operations, CPU timeout, cancellation and the PTC-to-Linux analysis chain. The r17 process-death checks and r21 SAF revocation checks cover their recorded cases. A successful offline chain does not establish nested Linux cancellation, shared-deadline expiry or network approval. The r26 [shipped production profile](production-profile-device.md) also passed a scripted-model PTC workspace read followed by offline Linux Python analysis, with distinct guest/App UIDs, confirmed retirement and durable Session evidence while locked with displays off. The ordinary Build 116 upgrade remains pending.

Focused host ToolRuntime and owner tests use simulated native transport and cannot certify Binder UID separation or Android process retirement. The [PTC lifecycle fixture](ptc-lifecycle-device.md), [SAF fixture](device-runtime-acceptance.md) and [PTC-to-Linux fixture](model-ptc-linux.md) own their separate device observations. Missing or uncertain evidence must remain visible rather than being inferred from registration alone.
