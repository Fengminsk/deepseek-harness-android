# Android model transport recovery acceptance

[中文](model-transport-recovery-device.zh.md)

This reference owns the keyless `model-transport-recovery` suite. It imports the shipped Android profile and runs its original DeepSeek HTTP/SSE adapter, AgentLoop, retry policy and Session persistence. It creates one dedicated Session in a fresh private home and sends one user message. Only the local model endpoint and isolated credentials are fixtures; no public account or paid request is used.

The model holds a partial SSE response. The native scenario waits for the original App's `session.live` notification containing that prefix before requesting an authenticated socket disconnect. The original normal policy then reconnects and completes the same turn and step. The fixture leaves the default retry budget and delay unchanged. It checks one consumed failed attempt, matching `llm/retry` and `llm/retry-started` identities, two requests on distinct connections, one final assistant response and one completed turn. Existing message blocks and all other request settings, including model, tools, thinking, system and unknown extensions, must remain unchanged. The original `dsh_session_log` extension may advance its incremental cursor: the fixture checks its bounded shape, same Session/header and forward cursor, and records event digests. It does not certify extension delivery, concurrent title uploads or JSONL-to-wire encoding. Added user/text blocks must match, in order, the original Session's runtime-context updates after retry started and before the final response; the public history and JSONL must agree. Context-generated user-role events remain separate from the one human submission.

Public history and the dedicated JSONL log must contain identical retry events. The result includes their ordered sequence numbers, both raw request digests, whether those bytes match, the validated runtime-context update count, incremental-log observations, the durable file digest and hashes of the shipped bootstrap/runtime. Diagnostics expose bounded counts, fixed request/failure stages and reasons, and every changed top-level field's type, size and raw/canonical JSON digests. Unknown field names are hashed; values, bodies, headers, credentials and exception messages are omitted. Model closure awaits the listener, accepted sockets and request handlers. Missing history, persistence, cleanup or native-owner evidence fails acceptance. The native scenario composes [production-profile isolation and closure](production-profile-device.md); it never changes credentials in the user's store. Unauthenticated local probes receive 401 and only increment a bounded counter; admitted malformed requests fail the fixture.

The copied private-home bootstrap compares canonical file paths to recognize direct execution through Android path aliases, then reads its runtime configuration before importing the model. A temporary resolver redirects only the evidence module's `@deepseek-ai/dsh-llm` import to that exact packaged runtime, verifies the resolved package location, then deregisters. It does not change the production bootstrap or provide a general package fallback. The packaged-import regression copies the fixture assets outside the repository and uses ordinary Node without tsx, `NODE_OPTIONS` or `NODE_PATH`; a directory symlink or Windows junction also exercises actual entry execution. The staged runtime remains read-only.

Use `runModelTransportRecoveryAcceptance({ invoke, signal })` from [the driver](acceptance-model-transport-recovery-device.mjs) inside the existing [screen and process protection owner](device-screen-protection.md). The caller supplies an invocation bound to its selected ADB/device and returns output only after that child closes. The suite requires `foregroundCarrier=service` and a device that remains locked and noninteractive. It opens no Activity, changes no Wi-Fi/data/VPN settings and never wakes or unlocks the display. The carrier has a 240-second suite deadline; readiness, consumed-prefix, retry completion and cancellation have separate finite waits.

The owning device runner uses these instrumentation arguments after integrating the suite; this command alone does not supply physical-panel protection or final process-retirement evidence:

```sh
adb shell am instrument -w -r -e suite model-transport-recovery -e foregroundCarrier service com.minnnng.dsh_android.test/com.minnnng.dsh_android.NativeRuntimeToolsAcceptanceInstrumentation
```

Focused host verification uses the original adapter and AgentLoop with real local HTTP sockets, including runtime context refreshed during retry. A separate permanent regression starts the actual staged Android bootstrap/profile in an isolated home, with explicit host storage/settings fixtures and a real local model, and verifies the completed JSONL. It keeps the original provider extensions and retry policy. The clean-EOF negative control remains nonretryable `STREAM_CLOSED`; cancellation during backoff prevents another request. The event validator and driver reject resubmission, changed steps, altered existing input/model/tools/settings, additions without matching durable runtime context, malformed incremental-log observations and unconfirmed cleanup. The scenario's JVM checks exercise typed diagnostic projection with the SDK JSON implementation. Host fixtures do not establish Android execution or persistence evidence.

```sh
node --import tsx --test apps/android/tool/model-transport-recovery.test.mjs apps/android/tool/acceptance-model-transport-recovery-device.test.mjs
node --import tsx --test apps/android/tool/model-transport-recovery-profile.test.mjs
node --test apps/android/tool/model-transport-recovery-packaged.test.mjs
node apps/android/tool/acceptance-model-transport-recovery-host.mjs
```

Device acceptance on 2026-10-28 passed with build 116 and test revision r31. The installed App SHA-256 remained `5cd11e06ab70a170235971f7a0140c982db992acf2c3c368066752e7089c7b41`; the test APK SHA-256 was `83fa170f2aaaaa4e43909b2a543db2beed1ffe35fdff36b58f3d99245f5b81c7`. The 13,344 ms scenario observed one submission, two model requests on distinct connections, one `TRANSPORT` retry, consumed partial text and completion in turn 1/step 1. The final reply at sequence 20 and turn end at 22 matched the dedicated JSONL. Typed diagnostics identified only `dsh_session_log` as changed, with stable settings and existing message blocks; its snapshots advanced from `afterSeq=-1, throughSeq=12` to `afterSeq=12, throughSeq=18`. The model listener and native owners closed. The outer protection owner separately confirmed host closure and absent device processes; all 10 samples showed both physical panels Off. Evidence is retained in `.cache/android/model-transport-116-r31-protected-20261028.json.result.json`, the corresponding `.json` protection report and `.json.live.txt` instrumentation log. The inner `nodeProcessRetired=false` field is not treated as retirement proof; that evidence comes from the outer report.

Earlier r28 and r30 results remain failed records under the same `.cache/android/model-transport-116-<revision>-protected-20261028` prefix. r28 failed while waiting for retry completion and lacked field-level diagnostics. r30 recorded a consumed prefix and second request, then rejected changed non-message fields despite unchanged existing message blocks. The subsequent full-profile host regression and r31 device result established the permitted incremental-log change; they do not retroactively certify either earlier run or establish r28's exact failure cause. The fixture correction changed no production retry policy or App binary.

A successful device result establishes active-model transport recovery on the shipped Android runtime under the test service carrier. It does not establish actual wireless disconnection/reconnection, public-network availability, prolonged Doze, killed-process resumption or long-running production AgentService active-task survival. The existing [AgentService recovery](agent-service-recovery-driver.md) checks service/Session availability during real radio changes; these two observations must not be combined into a claim that an active production task survived those changes.
