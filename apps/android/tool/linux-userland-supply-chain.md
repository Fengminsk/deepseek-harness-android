# ARM64 Linux userland candidate supply chain

English | [中文](linux-userland-supply-chain.zh.md)

## Fixed source and status

The inspected **data-only** candidate is [Alpine Linux 3.24.3 aarch64 minirootfs](https://dl-cdn.alpinelinux.org/alpine/v3.24/releases/aarch64/alpine-minirootfs-3.24.3-aarch64.tar.gz). Its official [SHA-256 file](https://dl-cdn.alpinelinux.org/alpine/v3.24/releases/aarch64/alpine-minirootfs-3.24.3-aarch64.tar.gz.sha256) gives `4d3f80afaebd447c5591a63a73bde380a149fe8b2d85488cafabb2ff97551f50`; the inspected archive was 4,029,999 bytes. [`linux-userland-source-lock.mjs`](linux-userland-source-lock.mjs) fixes this version, size and digest and checks a local copy. A hash **supplied by the same untrusted downloader** is insufficient. A future source update needs a reviewed lock change and a fresh archive and device test. This candidate is not bundled with the App, activated, or executable.

The inspected Alpine package database includes GPL-2.0-only packages such as BusyBox, apk-tools and libapk, plus other licenses. Redistribution obligations and notices have not been reviewed, so the archive must not be added to APK assets or represented as a distributable App image.

## App archive store (explicit internal operation only)

[`LinuxImageInstallManager`](../android/app/src/main/kotlin/com/minnnng/dsh_android/LinuxImageInstallManager.kt) exposes an explicit fixed-URL HTTPS transfer with redirects disabled, cancellation and a bounded duration. It is currently **not connected to a user-facing action or model tool**, so the App does not automatically download the image. [`PinnedLinuxImageStore`](../android/app/src/main/java/com/minnnng/dsh_android/PinnedLinuxImageStore.java) accepts only the pinned byte count and SHA-256, stages an inert archive with a source/license-status receipt under App `noBackupFilesDir/linux-userland/versions`, then atomically publishes the complete release. It rereads the archive and receipt after publication and on every offline inspection/restart. Interrupted or mismatched downloads cannot publish; a corrupt existing release fails closed and is preserved for diagnosis. The installer removes only its known incomplete staging directories. No archive contents are extracted, executed or exposed to a guest. File `fsync` precedes the atomic rename; containing-directory `fsync` is not portable here, so power-loss durability remains unproven.

The [Termux PRoot recipe](https://github.com/termux/termux-packages/blob/master/packages/proot/build.sh) identifies its fork, GPL-2.0 license, source hash and `libandroid-shmem`/`libtalloc` dependencies. Its upstream recipe was at 5.1.107.100 when checked on 2026-10-24; the separately reviewed source lock remains at 5.1.107.96. Do not silently replace the lock with a newer download: source review, reproducible Android build, dependency closure, APK native-library packaging and redistribution notices are still missing. The preflight's `libpocket_proot.so` descriptor is a required manifest slot, **not** evidence that such a binary exists. Audit Alpine's package licenses and any PRoot distribution obligations before shipping either artifact.

## Candidate installation contract

[`verifyLinuxUserlandArtifacts`](../runtime/linux-userland-image.mjs) checks the trusted manifest shape, ARM64 ABI, file sizes and SHA-256 for the rootfs and APK native launcher. It issues an opaque, in-process verification result; a forged JavaScript object cannot enter [`publishRootfsCandidate`](linux-userland-rootfs.mjs). That publisher copies and rehashes the archive, scans the complete tar stream, caps compressed size, entries, expanded bytes, individual files and path depth, then extracts into a fresh versioned staging directory. It rejects traversal, Windows path aliases, duplicate or case-colliding names, device/FIFO entries, symlink parents, escaping links and hardlinks to anything but an earlier regular file. Guest-root absolute symlinks are rewritten to relative links within the candidate. Hardlinks and symlinks are created only after all regular files are extracted, so tar cannot write through an archive-controlled link. It checks extracted regular-file bytes against archive-derived SHA-256, hardlink identity and the complete file tree. A successful candidate is atomically renamed under `versions/<sha256>` with a receipt; only the installer-owned incomplete stage is removed on failure. This guarantees complete visibility to a concurrent reader, but without a containing-directory `fsync` it does not guarantee persistence after a sudden power loss. [`verifyPublishedRootfsCandidate`](linux-userland-rootfs.mjs) lets a restarted process revalidate a published candidate against the independently reverified source image, full archive, receipt and extracted tree. Neither the writable receipt nor the candidate is an authority to execute. The module does not activate a version, garbage-collect older versions or run a guest. Activation and rollback need durable run references and an explicit version pointer before implementation.

## Android execution blockers

The App targets API 36. [Android's executable-file rule](https://developer.android.com/about/versions/10/behavior-changes-10#execute-permission) prohibits direct `execve()` of ELF files extracted into writable App home for targets 29 and above. The rootfs here is writable data, so its `/bin/busybox` and other ELF files must **not** be assumed runnable. PRoot is a path/ABI compatibility technique, not a security sandbox: [PRoot-Distro's own documentation](https://github.com/termux/proot-distro/blob/master/README.md) says it does not isolate processes, IPC or network. An APK-packaged native launcher and a tested guest execution mechanism are still needed.

The existing isolated-UID shell probe specifically checks that it cannot read App-private directories. A rootfs staged under the App UID's private `filesDir` is therefore not automatically visible to that process. Do not weaken that denial to make the guest run. Design a narrow, validated way to deliver immutable image data across this UID boundary, then test on a non-rooted device. Until that and W^X behavior, descendant cleanup, file/network broker enforcement and background lifecycle pass device tests, [`requireLinuxUserlandExecution`](../runtime/linux-userland-image.mjs) deliberately rejects execution with `LINUX_USERLAND_EXECUTOR_UNAVAILABLE`.

## Evidence recorded

- The official Alpine archive passed read-only inspection: 514 entries, 8,652,224 uncompressed file bytes, comprising 96 directories, 83 regular files and 335 symlinks.
- Unit tests cover digest drift, forged preflight results, atomic publication, traversal, links and resource limits. Windows disallows creating test symlinks, so link materialization remains unverified on this host.
- No Android Linux guest process has run from this pipeline. Do not label this feature a working container or offer it as an Agent tool.
