# Android 工作流 DSL Guest 契约

本文说明 App 私有的 `workflowDslNativeProgram` 适配器。私有所有者现已串接原生准入、回调绑定、执行、取消、终态收尾、子任务回收和已确认状态的释放。它没有注册成模型工具。Android profile 仍禁用原版 `workflow` 模型入口和 Node PTC 提供方；Node 测试通过不代表真机执行已验收。

App 先准入无授权工作流并持久化所有者，再启动全新的隔离 V8 Guest。原生准入程序是固定函数表达式，输入为 `{}`。原版工作流正文和 JSON `args` 只通过 `WORKFLOW_BEGIN` 进入 Guest。V8 只得到五种工作流回调的 `host.callAsync`；模型正文编译为 `AsyncFunction`，参数仅有 `agent`、`parallel`、`pipeline`、`phase`、`log` 和 `args`。该函数得不到 Node `fs`、网络、子进程、App 策略对象、宿主回调或授权。原生回调桥校验连续回调 ID，启动前持久预留每个子任务 ID，并在确认收尾前关闭所有子任务。

| 原版 DSL 操作 | App 私有适配器行为 |
|---|---|
| `args`、普通 JavaScript `return` | 使用有界无损 JSON 输入和返回。没有返回值时得到 `null`。与原版 DSH 的值复制行为一致，同一个普通值在多个分支重复引用时会分别复制；循环引用、稀疏数组、访问器、非有限数、类实例及过深或过大的值会使任务失败。 |
| `phase(title)`、`log(message)` | 按序发送进度回调；Android 进度日志要求非空且有界的文本，因此拒绝空文本。完成前会等待已排队的进度。 |
| `agent(prompt, {label?, phase?, provider?, model?, schema?})` | 经 App 预留 ID 和受限子任务后端启动一个子任务。不带 schema 时，完成后拼接文本块。带原版支持的对象根 schema 时，原版子任务运行时会在该子任务作用域安装校验 schema 的 `structured_output` 工具；`agent()` 只返回由权威工具事件确认的结果。子任务未提交该工具结果则返回 `null`，即使普通文本是合法 JSON。提供方和模型仍受后端锁定父任务的策略约束。启动、取结果或释放回调失败会使工作流失败，并要求原生端收尾。 |
| `parallel(thunks)`、`pipeline(items, ...stages)` | 每次最多 32 项。普通 thunk 或阶段错误使该项返回 `null`；基础设施、预算及不支持的选项错误使整个任务失败。子任务启动受总量和并发上限约束。 |
| 子任务工具边界 | 不带 schema 的子任务没有任何工具。结构化子任务只看到自己的 `structured_output` 结果工具；宿主全局工具（包括同名工具）仍隐藏，其他后注册的子任务局部工具由单调执行守卫阻止。启动子任务前会用原版 DSH 支持的 JSON Schema 子集校验 schema 语法。 |
| 其他 `agent` 选项、TypeScript/Node 专属语法或全局对象 | 不支持的选项和脚本解析错误均失败。V8 提供方运行普通 JavaScript，不是原版 Node PTC，也不包含 TypeScript 编译器。 |
| 丢弃钩子 Promise、回调超限、取消、返回时子任务仍在运行 | 未等待的异步钩子使任务失败；回调最多 128 次。原生取消或超时会关闭绑定的子任务端口，并持久化失败或待核查回执。进程死亡后不会重播脚本或自动恢复执行。 |

私有执行者将原版 `tool-workflow/run-start`、`agent-start`、`agent-end` 和 `run-end` 事件写入准确的父会话，并要求 `SessionStore.flush` 对每条记录确认有持久化监听者。成员进度在确认原生回调前落盘；`run-end` 等子级回收、原生结算及释放获确认后才写入。收尾未确认、缺少持久化监听者或客体报告的子级数量与记录不一致时，运行保持未结束且不发布完成结果。此会话日志不是独立的回调日志，也不能在冷启动后恢复执行。

App 私有工作流适配器的客体期限最长 120 秒，包含子任务回调；普通隔离脚本仍以五秒为上限。作用域租约必须覆盖请求的期限。此适配器只是安全性和语义集成步骤，不表示原版工作流能力已对齐。结构化子任务输出已有宿主集成测试，但尚无真机证据。向模型开放前，还需取得 Android 真机对子任务进度、取消、结构化输出以及冷启动收尾的端到端证据。
