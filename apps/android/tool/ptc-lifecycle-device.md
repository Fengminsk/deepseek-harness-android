# PTC process termination and SAF acceptance

English | [中文](ptc-lifecycle-device.zh.md)

## Summary

These opt-in checks test whether PTC leaves an interrupted file mutation unconfirmed and whether a revoked Android document grant stops further access. They use dedicated acceptance Sessions, UUID-derived directories and generated documents. They never reset App data or revoke a pre-existing document grant. A matching signed App and AndroidTest pair is required. The default [black acceptance window](device-runtime-acceptance.md) refuses a locked or non-interactive phone. Explicit service mode uses the [non-visual acceptance service](acceptance-foreground-service.md), including while locked, without waking or unlocking the phone. Neither mode guarantees physical screen power across installation or process termination; an external physical-power guard owns that requirement.

## Process termination

[The host runner](acceptance-ptc-process-death-device.mjs) verifies APK identities and the real Node carrier declaration. `--preflight-only` stops before device access. Device execution requires `--accept-force-stop`; an existing installation additionally requires `--allow-existing`. Installation uses `adb install -r`. Force-stop interrupts all work in that App, so the device owner must authorize this disruptive test. The runner does not clear storage, uninstall the App or remove audit records. It waits for its owned ADB preparation process and stdio to close before publishing success; a spawn error or unconfirmed cleanup fails the run even if a recovery result was received.

The carrier selects suite `ptc-process-death`, phase `prepare` or `recover`, and one generated `caseId`. Its private home ends in that UUID; its workspace ends in `.ptc-death-<caseId>`. Recovery accepts only the existing matching configuration and resumes Session `ptc-death-<caseId>`. [The Node fixture](device-runtime-acceptance/ptc-process-death.mjs) calls the original `write` tool through the real model PTC owner, native isolated callback adapter and durable callback journal. It holds the callback after the file has been written and synced, with the journal still at `dispatch-unconfirmed`. The private ready file includes the admission token; instrumentation status exposes only case/run IDs, Agent PID and output hash.

Pass `--foreground-carrier service` to the host runner, or `-e foregroundCarrier service` when invoking instrumentation directly. The runner passes the same selection to both phases, checks the preparation carrier-ready frame, and requires the recovered carrier plus native owners to close before accepting success. Missing, conflicting or incomplete carrier evidence fails. The deliberately killed preparation process has no graceful close acknowledgement; actual PID disappearance remains mandatory. Service mode is test scheduling support, not evidence that the production Agent service survives in the background.

After readiness, the host ties the exact run UUID to ActivityManager's isolated service process and independently observes its live PID. It force-stops the App and requires both the Agent and all isolated script processes to disappear. Fresh recovery requires a different Agent PID, the original file hash and the unchanged unconfirmed journal. Rebinding the original admission must fail with `ANDROID_TOOL_REPLAY` before any native rebind or tool execution. An unresolved mutation stays unresolved; this test neither replays it nor clears user recovery blocks. The carrier only reads the native receipt: `nativeReceiptState` must be `ADMITTED` or `INTERRUPTED_UNCONFIRMED`, and `nativeOutputAbsent` must be `true`. The host preserves these observations as `nativeReceiptInspection: read-only-unconfirmed`; it does not invoke or certify the native cold-recovery transition.

## Document search and revocation

[The test provider](../android/app/src/androidTest/java/com/minnnng/dsh_android/PtcSafAcceptanceProvider.java) lives only in the AndroidTest APK. It retains `MANAGE_DOCUMENTS` and URI-grant enforcement. Its explicit [bound control service](../android/app/src/androidTest/java/com/minnnng/dsh_android/PtcSafAcceptanceControlService.java) requires the App's signature-level `RUNTIME_ACCEPTANCE` permission, runs under the provider UID and accepts only fixed operations plus the bound fixture UUID. It creates two fixed text files, grants one generated tree to the fixed target App and returns that URI. The App persists the grant through Android's normal resolver. No command accepts an arbitrary filesystem path, document URI or target package.

The App binds explicitly with `BIND_AUTO_CREATE` from its existing acceptance carrier and holds the binding throughout the fixture. The test service has no foreground-service or UI startup. Its Messenger checks Android's `sendingUid` against the fixed target App UID, the bound UUID, request number and operation. The App checks the reply's kernel-supplied UID against the instrumentation APK UID and requires the same control PID throughout. Binding, disconnect and control-response failures remain failures; unknown work is not retried. Cleanup releases only the generated persisted grant, removes only that fixture and unbinds even on failure. A binding release does not certify that Android destroyed the test process; the host retirement owner verifies actual process removal.

On devices that block cross-package cold starts, the opt-in [bootstrap instrumentation](../android/app/src/androidTest/java/com/minnnng/dsh_android/PtcSafBootstrapInstrumentation.java) targets only `com.minnnng.dsh_android.test` and its same-named process. Shell starts it before the main SAF instrumentation. It self-binds the control service under the independent test UID without creating documents or granting any URI. Its readiness frame includes the exact token, PID, UID, distinct App UID and bounded lease of 60–600 seconds. It opens no window, starts no foreground service, holds no wake lock and does not wake or unlock the device. Lease expiry or service loss fails; bootstrap readiness alone is never SAF acceptance.

[The host helper](acceptance-saf-bootstrap.mjs) exports `withSafBootstrap({ adb, serial, logPath, leaseMillis? }, operation)`. The log path must be new. The callback receives an `AbortSignal` and must own and join its main instrumentation subprocess and other resources before settling. The helper refuses an existing test-package process, waits for a complete token-matched readiness frame and verifies its actual PID/UID through full process observations before invoking the callback. It aborts on premature bootstrap exit, waits for main teardown, force-stops only its test package, confirms the old PID and every process under its UID have disappeared, and joins its owned ADB client before returning `{ value, bootstrap }`. Main failure or unconfirmed cleanup remains failure. The external screen guard still owns physical-display protection and final App/full-process cleanup. The main native and PTC SAF checks retain their real cross-UID persist/revoke assertions.

[The native instrumentation](../android/app/src/androidTest/kotlin/com/minnnng/dsh_android/PtcSafAcceptanceInstrumentation.kt) checks bounded literal search, waits until a second search has entered the provider, releases only its generated grant and joins cancellation. It rejects a returned result after revocation, checks that subsequent read/search calls fail, removes its own provider files and compares every pre-existing persisted grant's URI and flags. An unrelated provider exception is not accepted as cancellation. The synthetic provider control remains available after revocation through the signature-protected binding, not through a retained document read grant.

Search and image reads use [the raw provider reader](../android/app/src/main/kotlin/com/minnnng/dsh_android/DocumentProviderRead.kt) only after their existing persisted-grant and document checks. The reader calls `ContentProviderClient.openAssetFile(uri, "r", signal)` rather than the resolver's read-only MIME conversion, which can discard the cancellation signal in `DocumentsProvider`. It uses `AssetFileDescriptor.createInputStream()` to preserve the asset offset and declared length, closes the stream, descriptor and client, and retains the original exception when cleanup also fails. Image verification still opens two independent streams. The native search report records `openDocumentSignalPresent`, requires it for success, and preserves cleanup failures as suppressed exceptions. Its cancellation and worker-retirement deadlines are unchanged.

[The PTC SAF fixture](device-runtime-acceptance/ptc-saf.mjs), suite `ptc-saf`, sends search/read through original `android_files`, real `NativeIsolatedToolCallbacks` and `AppDocumentSearch`. The carrier supplies only the generated root and handles `acceptance.saf.revoke` for that exact root. The fixture requires a distinct isolated UID, one native search lifecycle, four durable callback results and refusal of both read and search after revocation. The native in-flight test and PTC test cover different assertions; neither substitutes for the other.

Both `PtcSafAcceptanceInstrumentation` and the Node carrier's `ptc-saf` suite accept `-e foregroundCarrier service`; the default remains `activity`. The native probe has a 90-second service lease. Carrier failure cancels the search owner and waits for the search worker before lease release. Successful results include carrier identity, closure and observed lock/display state. These are framework observations, not captured pixels or proof of physical panel power.

## Verification limits

Run the focused host regression with `node --import tsx/esm --test apps/android/tool/acceptance-ptc-process-death-device.test.mjs`. It actually terminates a child Node process after a real ToolRuntime write and reloads its real Session and journal in another process. Host SAF tests use the real tool/callback/search owners with an explicitly simulated Android transport. Negative controls reject corrupt markers, incomplete searches, duplicate results and evidence that names a different run. Host success does not certify Android process retirement, URI grants, Binder cancellation or release APK packaging.

Run `node --test apps/android/tool/acceptance-saf-bootstrap.test.mjs` for readiness, process identity and teardown negative controls, including a barrier that prevents early success while main cleanup is still running. Run `node apps/android/tool/acceptance-saf-control-host.mjs <android.jar>` for the real Java request-policy checks and compilation of all three independent components with no App or Kotlin dependencies. Run `python apps/android/tool/audit-saf-test-apk.test.py` for dependency-audit negative controls. After the AndroidTest APK is built, run `python apps/android/tool/audit-saf-test-apk.py --test <test.apk> --platform <android.jar> --report <new-report.json>`. This inspects the actual DEX closure reachable from the Provider, control service and bootstrap instrumentation, including synthetic helpers, initializers, catch types and member signatures; only the test APK and SDK may resolve dependencies. It never falls back to the main App. Static linkage does not certify Binder delivery, reflection or device behavior.

Run `node apps/android/tool/acceptance-document-provider-open.mjs <kotlin-compiler-config.json>` with a local `compilerCp` classpath to compile the production Kotlin reader, `DocumentBinaryReadAccess` and `DocumentSearchJob` against explicitly simulated Android API endpoints. This checks independent image verification reads, bounded asset data, cancellation while opening, null/dead providers and preservation of failures during cleanup. It keeps its uniquely allocated host outputs under the project cache. These host checks do not prove Android Binder behavior; native search and image cancellation each need their own device evidence.

## Dev Note

Each device decision requires the corresponding saved report. The r20 PTC SAF report confirms the independent test UID, search/read callbacks, revocation and process retirement with self-target bootstrap and main-App instrumentation. The separate native in-flight search failed to retire; its cancellation fix still requires a rebuilt App and device retest. Image reads sharing that fix are not device-certified by the PTC or native-search result. Earlier device logs identify startup-policy refusal of both the broadcast and cross-package service cold start; the separately identified Kotlin dependencies were a latent defect, not evidence of a crash during those attempts. Retain failed fixture records for diagnosis instead of rewriting them into successful or replayable state.
