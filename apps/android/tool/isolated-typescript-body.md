# Android TypeScript body preparation

English | [中文](isolated-typescript-body.zh.md)

The original Node PTC provider wraps a model program as an async function body, then calls Node's `stripTypeScriptTypes()` with type erasure. [`isolated-typescript-body.mjs`](../runtime/isolated-typescript-body.mjs) uses the same wrapper and built-in API before preparing a trusted Android script request. It accepts erasable TypeScript, including annotations, interfaces, type aliases, generics, `as` and `satisfies`; it rejects syntax requiring emitted runtime code, such as enums, namespaces and constructor parameter properties. Top-level `await` and `return` remain function-body syntax. This host step does not invoke the resulting function or grant a file, network or tool capability.

The compiler checks the original and resulting UTF-8 byte limits against the native 64 KiB program ceiling, rejects unpaired surrogate code units, requires the wrapper to survive erasure, and checks that every physical line retains its UTF-16 length. It then compiles the stripped body as an `AsyncFunction` argument without invoking it; an attempt to escape the original wrapper cannot run in the App host. The frozen result contains the stripped JavaScript body, hashes of both versions and line-count metadata. `originalTypeScriptLocation()` maps a location in the **string passed to native AsyncFunction** back across the single native `'use strict';` prelude line. Native receipts currently expose status codes rather than V8 stack positions, so this is preparation metadata, not a claim that runtime diagnostics have mapped source locations.

`prepareIsolatedTypeScriptRun()` accepts a trusted App-owned script request, rejects accessors and additional request fields, replaces only its program with the compiled JavaScript, then uses the existing execution preflight to bind the selected Session, run ID, deadline and trusted policy. The returned original source and both hashes must be written to the durable owner record before native admission when this route is integrated. The current manual native page continues to use its own JavaScript entry. The model-facing PTC and workflow gates remain closed: the V8 guest still lacks original Node APIs, `tools.*` callback parity, TypeScript preparation wiring, runtime source diagnostics and normal-device acceptance. Node's type stripping API is experimental and the development host and packaged Android Node versions must be checked together before enabling it.

Run `node --test apps/android/tool/isolated-typescript-body.test.mjs`. The tests compare transformed output with the original provider's wrapper and Node stripper, execute one stripped example only in a test, reject non-erasable and wrapper-escape forms, verify no host code invocation, and cover UTF-8 limits, source positions and trusted request ownership. These host tests do not execute the Android V8 guest.
