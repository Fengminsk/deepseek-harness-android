# Android workflow DSL guest contract

This reference describes the App-private `workflowDslNativeProgram` adapter. The private owner now sequences native admission, callback binding, execution, cancellation, settlement, child retirement and confirmed release. It is not registered as a model tool. The original `workflow` model entry and the Node PTC provider remain disabled in the Android profile; a passing Node test does not establish device execution.

The App admits an ungranted workflow and persists its owner before launching one fresh, isolated V8 guest. The native admission program is a fixed function expression and its input is `{}`. The original workflow body and JSON `args` enter the guest only through `WORKFLOW_BEGIN`. V8 receives `host.callAsync` for the five workflow callbacks; the model body is compiled as an `AsyncFunction` with only `agent`, `parallel`, `pipeline`, `phase`, `log`, and `args` parameters. No Node `fs`, network, subprocess, App policy object, host callback, or grant is passed to that function. The native callback bridge validates consecutive callback IDs, reserves every child ID durably before start, and closes all children before confirming retirement.

| Original DSL operation | App-private adapter behavior |
|---|---|
| `args`, plain JavaScript `return` | Bounded lossless JSON input and return. An absent return becomes `null`. Repeated references to the same plain value are copied into each branch, as in the original DSH materializer; cycles, sparse arrays, accessors, non-finite numbers, classes, and excessive depth or size fail the run. |
| `phase(title)`, `log(message)` | Ordered progress callbacks; empty text is rejected because the Android progress journal requires non-empty bounded text. Pending progress is drained before a completed result. |
| `agent(prompt, {label?, phase?, provider?, model?, schema?})` | One child through the App reservation and confined child backend. Without a schema, completed text blocks are joined. With a supported object-root schema, the original subagent runtime installs its schema-validated `structured_output` tool in that child's scope, and `agent()` returns only the result committed by the authoritative tool event. A child that ends without that event yields `null`, even when its plain text contains valid JSON. Provider/model choices remain subject to the backend's frozen-parent policy. A start, result, or disposal callback failure fails the run and requires native retirement. |
| `parallel(thunks)`, `pipeline(items, ...stages)` | Up to 32 items per call. Ordinary thunk or stage errors yield per-item `null`; infrastructure, budget, and unsupported-option errors fail the whole run. Agent starts obey the configured total and concurrent limits. |
| Child tool scope | A child without `schema` has no tools. A structured child sees only its own `structured_output` result tool. Host-wide tools, including one named `structured_output`, remain hidden; all other late scoped tools are blocked by a monotonic execution guard. Schema syntax is checked against the original DSH supported JSON Schema subset before child publication. |
| Other `agent` options, TypeScript/Node-specific syntax or globals | Unsupported options and script parse errors fail. The V8 provider exposes plain JavaScript, not the original Node PTC or a TypeScript compiler. |
| Dropped hook promise, callback overrun, cancellation, child still running at return | An unjoined asynchronous hook fails the run; callback count is capped at 128. Native cancellation/timeout closes the bound child port and persists a failed or unconfirmed receipt. No script replay or automatic resume occurs after process death. |

The private owner writes the original `tool-workflow/run-start`, `agent-start`, `agent-end`, and `run-end` events into the exact parent Session and requires `SessionStore.flush` to confirm a storage listener for every record. Accepted member progress is flushed before the native callback is acknowledged, while `run-end` waits for confirmed child retirement, native settlement and release. An unconfirmed cleanup, missing storage listener or guest child count mismatch leaves the run open and withholds completion. This Session log is not an independent callback journal or a cold-recovery engine.

The App-private workflow adapter has a finite 120-second guest deadline including child callbacks, while ordinary isolated scripts retain the five-second cap. Its scope lease must cover the requested deadline. The adapter is a safety and semantic integration step, not a claim of original workflow feature parity. Structured child output is verified in host integration tests, but not on a device. Model exposure requires Android end-to-end evidence for child progress, cancellation, structured output, and cold-start retirement.
