# Android SAF image recorded Session check

English | [中文](saf-image-recorded-session.zh.md)

After the Android runtime is staged as described in the [build instructions](../README.md), run `pnpm run test:android:recorded` from the repository root. The manifest in `recorded-sessions.json` lists Android-profile scenarios; `scenarios/saf-image.json` supplies this scenario's user request and model tool call independently of the expected output. The command starts the staged Android profile, supplies a synthetic SAF image through the native request protocol, lets the model call `android_files/read_image`, and checks that the resumed model request references the uploaded image file. It then closes the runtime, reads the persisted `session.v4.jsonl`, restarts the profile under the same private home, and confirms that the Session result still refers to the same attachment without rewriting the log or storing raw image bytes. The lane rejects missing or stale staged runtime source files and missing expected output, then removes its temporary private home on success or failure.

The committed [expected projection](expected/saf-image-session.expected.json) records only stable user, request, tool and completion fields from the reopened Session. Random message IDs, times, the content-addressed attachment ID and workspace instruction text are omitted. The test compares this projection on every run. After an intentional behavior change, `pnpm run test:android:recorded:refresh` rewrites it for review. The command does not update the original `snapshots/` corpus.

This is a first-class Android owner-local recorded-Session lane, **not** the canonical `pnpm run test:snapshot` lane. The canonical lane currently accepts only `headless`, `sdk`, `sdk-minimal`, `acp` and `web` profiles and requires processes to start through `dsh`; Android ships `bootstrap.mjs` behind a native RPC owner instead. This command does not stage the runtime, run in the repository-wide CI snapshot aggregate, or establish real SAF provider, Binder, Keystore, model service or device behavior. An Android device lane and broader scenario corpus remain necessary.
