# 后台任务完成通知恢复验收

中文 | [English](task-completion-recovery-acceptance.md)

本文记录 Android Agent 进程退出后的通知投递行为。实时驱动确认任务成功时，完成回执与结束序号水位一起提交。恢复时只读取序号与水位一致的已提交回执；恢复可以显示通知，不会重新启动任务，也不会根据空闲的会话推断成功。无效和过期回执由通知写入线程清理；有效回执每次最多八条进入主线程。投递失败时保留回执，供后续 Service 实例恢复；这也包括权限检查后、系统接收通知前权限发生变化的情况。仅在系统接收通知或通知按规则被抑制后才确认回执；确认回执不会改变会话结果。

Node 启动后的 Service 销毁回调会先记录运行时中断，再执行可选的资源清理；即使清理失败，专用进程仍须退出。如果 Android 未调用销毁回调就杀死进程，冷启动恢复会把孤立的进程租约视为中断。这两条路径都不会把未结束的任务标为成功。

在仓库根目录运行 `node apps/android/tool/acceptance-task-completion.mjs`。宿主测试覆盖重复完成抑制、正在查看会话时的通知抑制、延迟持久化、关闭时排空、回执编码和恢复快照筛选。宿主测试无法证明 Android 通知权限、真实 Service 销毁、前台服务超时或进程调度行为。

有手机可用时，先记录 APK 哈希、Android 版本、通知权限、会话 ID 和最后提交的结束序号。在查看其他页面时完成任务，确认一条简短通知可打开对应会话。在查看任务会话时再完成任务，确认不会重复提醒。另一次任务完成后，在回执提交后立即终止 Agent 进程并重新进入应用；确认待恢复通知最多出现一次，会话保留原结果，而且模型与工具调用都没有重跑。再分别使用关闭通知权限、中断任务和重新进入前断网的条件重复检查。判断通知缺失原因前，先核对会话与任务状态。

宿主测试通过不等于上述真机验收通过。Android 可能不调用 `Service.onDestroy` 就终止进程；即使回执已经提交，系统也可能拒绝或推迟通知。不能把中断任务报告为成功，也不能自动重试结果未知的工具调用。
