# APK 升级、离线与进程重启验收

[English](upgrade-offline-acceptance.md) | 中文

Android APK 不包含 Windows 原生二进制文件。为在 Windows 主机运行包内 JavaScript，此脚本会先核对包元数据一致，再仅补入暂存包的两个 Windows 测试绑定。JSON 结果会标明这项替换。

运行 `node apps/android/tool/acceptance-apk-upgrade-offline.mjs [旧版.apk] [新版.apk]` 执行**主机侧**检查。默认读取已归档的构建 54 APK 与当前调试 APK。提取器校验两个 APK 内置运行时的 SHA-256，并拒绝危险 ZIP 路径与链接。测试从真实 APK 提取两代 Android profile，在独立 Node 进程中共用同一持久目录；所有网络流量只允许访问合成的本机账号与模型服务。旧版进程完成登录、一次模型回复和会话写入，再开启另一轮流式请求，并在完成前被终止。新版断网冷启动后重新打开账号授权、已完成及被中断的会话，保留内置模型，不重放浏览器登录、令牌交换或任何模型请求；联网后恢复模型目录，再次冷启动检查幂等。新版还单独验证了另一轮流式请求中断后连续两次离线冷启动，用户消息和模型请求均未重复。为控制磁盘占用，脚本先提取旧运行时，终止旧进程后删除其生成的提取目录，再提取新运行时；共用的持久目录保留到测试结束，且两代运行时摘要必须不同。所有测试进程停止后，脚本默认删除生成的持久目录及临时 ZIP。显式添加 `--retain-home` 可保留测试目录供审计；JSON 结果会标明是否已删除。

`python apps/android/tool/extract-apk-runtime.test.py` 检查提取器的反例。`node apps/android/tool/task-recovery-smoke.mjs` 单独覆盖流式回复和待批准 Shell 调用期间的进程终止、结果未知、待处理输入保留和不自动重放。`node apps/android/tool/account-recovery-smoke.mjs` 单独覆盖当前暂存 profile 的 HTTP 503、连接失败和账号拒绝。`node apps/android/tool/acceptance-document-access.mjs` 检查主机可验证的 SAF 读取边界与文件版本。它们是不同证据，不能合并宣称已验证 Android 进程死亡、系统安装升级、Keystore 或 ContentResolver 授权持久化。

真机验收仍须在旧版安装状态下准备真实账号、已完成及进行中任务、已持久授权的 SAF 目录；分别断网与恢复、强行终止 Agent 进程；随后**不清除应用数据**安装新版，核对账号、模型目录、会话、待处理任务、授权访问与撤销、通知，以及模型和工具没有重复副作用。记录安装包版本与哈希、`dumpsys package` 数据目录身份、任务／会话 ID 和时间戳。主机检查不能证明 Android 升级会保留实际应用数据，或系统杀进程一定调用 `Service.onDestroy`。

SAF 文本分页在首次读取时建立应用私有的不可变快照，并重新打开提供方文件核对一次 SHA-256；后续页按内容版本读取同一快照，不会把大小和修改时间均未变化的另一份内容拼接进来。每页仍核对持久授权、原相对路径、文档 URI 和提供方元数据；撤销授权或移动文件后继续分页会失败。重新从第 0 页读取会建立新快照，取得新的内容版本。单文件快照最多 256 MiB，缓存总额最多 512 MiB、最多 8 份，30 分钟未使用后清理，且保留至少 128 MiB 可用空间；缓存被系统清除、到期或被新快照逐出时，需要从头读取。同一应用进程中的分页读与逐出使用同一临界区，避免正读取的快照被并发清理；系统在进程外清除应用缓存后仍可能使下次读取失效。这里保留的是快照时的内容；若提供方在快照完成后悄然改写同一 URI 且不更新元数据，继续读取仍会显示旧快照，直到主动重新打开。真实 ContentResolver 提供方、进程重启后的缓存保留和授权撤销竞态仍需真机验收。

SAF 目录列表与按名称解析相对路径时，每级最多扫描提供方返回的 10,000 项。相对路径在访问提供方前限制为 4,096 字符和 64 级；目录或路径超限时会提示用户通过系统选择器直接授权更近的子目录。主机文档访问测试覆盖这些限制，提供方游标行为仍需真机检验。
