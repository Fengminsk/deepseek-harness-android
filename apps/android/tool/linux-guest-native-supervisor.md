# Unshipped Linux guest native supervisor

English | [中文](linux-guest-native-supervisor.zh.md)

`linux_guest_supervisor.c` is a source-level Android ARM64 feasibility component. `DSH_BUILD_LINUX_GUEST_SUPERVISOR` is **OFF by default** in the App CMake file. Ordinary APK builds do not compile or package this executable, PRoot, its loader, or Alpine. There is no Service caller or Agent tool. Explicitly building the target does **not** authorize including it in an APK.

The future fixed diagnostic invocation is `libpocket_linux_guest_supervisor.so PARENT_PID RUN_UUID ISOLATED_ROOTFS_DIR`. The parent must be a trusted, per-run `isolatedProcess` Service and must concurrently read stdout. The supervisor requires a canonical UUID, a canonical isolated-UID-owned rootfs directory with no write bits, and PRoot/loader candidates alongside its own APK-installed executable in a directory inaccessible for writes. It opens both files without following symlinks, checks locked SHA-256 digests against the **same read-only descriptors**, uses descriptor 4 for the launcher `execve`, and exposes only its pinned loader descriptor 6 as `PROOT_LOADER=/proc/self/fd/6`. Its directory is unwritable by the isolated UID, and the descriptors remain open across the checks to prevent a same-UID path replacement. The trusted App must separately verify the rootfs image digest and immutable package revision. No untrusted command arguments are accepted: the only proposed guest command is `/bin/true`. Whether Android SELinux permits `execve("/proc/self/fd/4")` or PRoot can use the descriptor-backed loader on this phone remains a device-test question.

After digest verification, the supervisor creates separate event, discarded guest-output, and exec-failure pipes before fork. The child puts the PRoot event pipe at descriptor 3, retains only that control descriptor and the read-only pinned loader descriptor 6 across execution, closes every other unexpected descriptor using kernel `close_range`, and supplies a fixed environment with the run UUID. If `close_range` is unavailable, it refuses to launch. `execve` failure cannot be mistaken for a successful trace drain. The parent limits output to 64 KiB, trace bytes to 2 MiB, and runtime to 30 seconds. Its stdout forwards only parsed `DSH_TRACE_V1` events; guest output is counted and discarded. Success requires `ROOT`, `ARM`, ordered lifecycle events, `DRAIN`, pipe EOF, successful tracer exit, no active observed tracee, and `waitpid` exhaustion as a subreaper. The App's `LinuxTraceeEventWire` and durable run journal must still verify and commit the result independently.

Cancellation, deadline, malformed events, or App parent death trigger process-group termination while the tracer PID remains unreaped. The subreaper also reads its own `/proc/self/task/<pid>/children` list and kills direct children before reaping them; it repeats this after intermediary parents exit so adopted descendants become visible. Historical trace PIDs are never signalled because they may have been reaped and reused. Even after all pipes close, the supervisor applies the same retirement pass and refuses success on unexpected adoption, an unreadable or truncated child list, or children not reaped within two seconds. This is **not** evidence that escaped descendants always die on a phone. A future Service must use one fresh isolated UID per run, tear it down on uncertainty, and verify no descendants survive with real device tests. PRoot translates paths but is not a sandbox; the isolated UID and broker policy must withhold App-private paths and network access. A failed or interrupted run must not commit a success receipt; a package upgrade must invalidate staged image and pinned executable identity before any retry.

Host evidence so far: [the acceptance script](acceptance-linux-guest-native-supervisor.ps1) builds the ARM64 source with Android NDK 28.2.13676358 using `-Wall -Wextra -Werror` and checks AArch64 PIE, `/system/bin/linker64`, 16 KiB load alignment, and exclusion from ordinary APKs when one is supplied. It builds the exact SHA-256 and direct-child snapshot parser C sources to WebAssembly; [parser vectors](acceptance-linux-guest-children.mjs) cover malformed, oversized, and capacity-truncated PID lists. These host checks do not exercise Android process adoption or SELinux. It has not run on a phone, loaded PRoot, or run Alpine. The license/source-delivery gate in [PRoot distribution review](linux-proot-candidate/DISTRIBUTION.md) must be resolved before any debug or production APK can include the candidates.

Parity boundary: original DSH [local sandbox](../../../packages/sandbox/sandbox-local/README.md) confines host commands and descendants; its [sandbox policy](../../../packages/sandbox/sandbox-policy/README.md) governs file effects while network policy is separate. This fixed `/bin/true` guest experiment does not implement those general command, workspace-write, or network contracts. The shipping Android `android_linux` utility remains the bounded model-facing path until real isolated-UID execution and recovery are proven on a device.
