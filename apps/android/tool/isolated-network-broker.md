# Isolated guest HTTP capability foundation

English | [中文](isolated-network-broker.zh.md)

`IsolatedNetworkBroker` is an App-side network capability for the internal isolated V8 guest. `IsolatedScriptRunController` accepts an optional App-owned network policy backed by an active execution-policy lease, an exact host set and a durable journal; the guest has no network API or host object without an explicit host policy. **There is no model-facing PTC provider, policy screen, user approval flow or production caller.** A nonempty host policy requires an App-private `IsolatedNetworkJournal` and a stable caller-owned UUID for each `get(callId, url)` call; the one-argument method cannot bypass that requirement. This does not establish PTC or workflow parity.

The broker accepts only a normalized, exact ASCII DNS hostname on an explicit HTTPS allowlist. Its default `Policy.off()` is empty. It rejects IP-literal URLs, userinfo, fragments, non-443 ports, local/special-use hostnames, non-ASCII URL text, oversized URLs, unallowlisted redirects, non-public IPv4 DNS answers, and an IPv6-only result. It exposes GET only: no caller-supplied headers, body, cookie jar, auth, WebSocket, client certificate, or proxy. The request quota is 64 calls within a five-minute broker lease, up to three redirects, 1 MiB response bytes, 32 KiB headers, and a ten-second deadline per call. Each redirect is resolved, reauthorized and pinned independently. An invalid result closes the call; it never widens host policy.

Results distinguish `POLICY_DENIED` for rejected hosts, URLs, redirects or quota from `DEADLINE_EXCEEDED` when the call's total time runs out, including after a redirect. A response that exceeds the body or header bound returns `RESPONSE_TOO_LARGE`; it is not treated as a host-policy violation. `AUDIT_UNAVAILABLE` means admission could not be durably confirmed before network I/O, `AUDIT_FULL` means the persistent audit quota is exhausted, and `AUDIT_UNCERTAIN` means an admitted call failed unexpectedly or its terminal sync failed. The broker revokes further I/O and attempts to record that uncertainty even when the transport throws an unchecked exception. Reusing the call ID returns `REPLAY_DENIED` without DNS or transport. A caller may choose a shorter per-call deadline, never longer than ten seconds. No partial oversized response is returned.

`AndroidNetworkJournal.open(context)` accepts only the `:agent` process and supplies Android directory fsync to the journal. Before DNS, the journal writes an `ADMITTED` record with the call ID, normalized host and timestamp, then syncs the file and directory. After the broker classifies an outcome, it atomically replaces the record with a terminal status, whether transport was entered, and a directory sync before releasing that outcome. A crash or failed terminal sync leaves the server effect uncertain; the caller must not mint a new ID and retry automatically. The audit omits URL paths, query strings and response content. It retains every call ID; admission fails closed at 8,192 files or when current files plus one maximum-sized receipt would exceed 16 MiB. Crash-left temp files count toward both limits. There is no automatic eviction, so a product retention and export policy is still needed before enablement.

`PinnedTlsTransport` connects an already checked `Inet4Address` through the socket route returned with its DNS answer, then wraps that **existing socket** in TLS using the DNS hostname for SNI and HTTPS endpoint identification. The HTTP layer never resolves the hostname again or selects a process-default socket. It accepts bounded HTTP/1.1 fixed-length, chunked or close-delimited responses; it does not decompress bodies or retain response cookies. This prevents validate-DNS-then-connect-by-host rebinding and default-network changes from silently moving the TCP request to another route. Android documents the selected route in [`Network.getSocketFactory()`](https://developer.android.com/reference/android/net/Network#getSocketFactory()) and hostname verification in [SSLParameters](https://developer.android.com/reference/javax/net/ssl/SSLParameters). The conservative IPv4 exclusions include IANA's [special-purpose address registry](https://www.iana.org/assignments/iana-ipv4-special-registry). IPv6 routing is intentionally unimplemented, not implicitly allowed.

The internal bridge exposes only `host.call({action:'HTTPS_GET',callId,url})`; the App checks an exact host set and a per-lease network-call budget, then uses the audited broker. Network-only leases require no file workspace and show an empty `host.grants`. The bridge limits each body to 64 KiB, returning UTF-8 as `bodyText` or other bytes as `bodyBase64`; an oversized body settles as `RESPONSE_TOO_LARGE`. A network audit whose terminal state cannot be synced withholds script output. This is **not a live user grant**. Blocking Java `InetAddress.getAllByName()` is never used by the broker. `AndroidDeadlineResolver` implements its required resolver interface using Android's asynchronous [`DnsResolver.query(Network, ..., TYPE_A, ...)`](https://developer.android.com/reference/android/net/DnsResolver) on API 29+. It selects a non-null, validated, Internet-capable default [`Network`](https://developer.android.com/reference/android/net/ConnectivityManager#getActiveNetwork()), checks that a process-bound network does not differ, specifies that Network in the query, and checks the default network again before returning. The result carries both a snapshot of the DNS answers and a socket factory captured from that exact Network; each redirected hop gets its own result. If the selected Network disconnects, sockets from its factory cease to work rather than falling back to a new default. DNS bypasses caches, uses a cancellation signal, rejects absent or excessive answers, and discards late callbacks. A monotonic deadline bounds the caller's wait; a single-worker, zero-queue executor bounds the number of query-start Binder calls that could remain stuck. After potentially blocking network-state reads and `DnsResolver.getInstance()`, it checks cancellation and the deadline again immediately before `query`. API 28 fails closed because this asynchronous API is unavailable. Android's query dispatch can still race with expiry immediately after that check; absence of a late DNS packet is not claimed.

The route link is structural: the transport has no process-default socket fallback, and Android's selected-Network factory is the only socket source supplied by its resolver. The resolver checks Network eligibility again in the DNS callback; a subsequent default-network or VPN switch cannot redirect an already bound socket, though a request may still use the previously selected Network while it remains connected. Revocation closes a registered active TCP socket and marks the lease cancelled; DNS waiting notices the same token within its polling interval and cancels Android's query signal. Route creation checks revocation while waiting and reclaims sockets returned after the caller leaves. A single-worker, zero-queue route opener bounds the caller's wait for socket creation and closes sockets returned after expiry; if a platform call ignores interruption, later attempts fail closed until that worker returns. The transport rejects an expired deadline before setting any socket timeout, since `SO_TIMEOUT=0` means an infinite wait. A daemon timer closes the underlying TCP socket at the total deadline, including TLS handshake and request write. These are host-tested abort mechanisms, not device-proven hard timing guarantees for Android Binder, native TLS or process death. Revocation cannot undo bytes already sent to a server or prove that no late remote effect occurred. No device validation has been performed.

Host contract checks: `node apps/android/tool/acceptance-isolated-network-broker.mjs` and `node apps/android/tool/acceptance-android-dns-resolver.mjs`. They test audit admission and terminal failures, duplicate IDs, storage quota and crash-left temp accounting, active-socket closure, DNS revocation, route propagation on redirects, factory-only socket creation, pinned destination, answer snapshots, late callbacks, deadlines, saturated query-start capacity and invalid responses. The Android instrumentation suite compiles a network-only lease with synthetic DNS and transport, a denied host and a malformed call; it has not run on a device. Neither host checks nor compilation execute Android `DnsResolver`, perform real TLS, or prove Android UID/network policy. Before enabling a model-facing network tool, add durable user approval and audit retention, then test TLS validation, proxy bypass, redirects, network switching/loss and process death on a non-rooted device. The isolated process must not receive INTERNET or direct socket authority; only App-side broker calls may perform approved network I/O.

The App-owned execution-policy lease synchronously cancels the broker when a run, parent run, or policy is revoked. The broker caps every call by the earliest parent or child lease expiry. A revocation after DNS and before transport entry therefore prevents the request write; an overlapping or already sent request may still have a remote effect and is not treated as confirmed success.
