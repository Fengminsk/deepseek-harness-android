# Android 任务中心的独立作业

[English](task-center-jobs.md) | 中文

任务中心最新的 `tasks.list` 响应除各会话回合历史外，还包含当前进程中 `ctx.jobs.snapshot()` 的独立投影。因此，即使从后台设置进入、未选中任何对话，也能看到独立作业。列表显示状态、生产方进度和所属会话，并可直接打开既有输出页面。输出页面仍使用原版不消耗模型游标的 `job.follow` 流；有归属的作业以确切的所属会话进行访问隔离。

无归属作业在未提供会话的情况下进行跟踪。其停止按钮调用 `tasks.killUnownedJob`，后者在不提供调用方的情况下调用原版注册表的 `kill`；注册表会拒绝此路径尝试停止有归属作业。有归属作业继续使用带所属会话的 `job.kill`。停止回执不等于执行已结束：页面等待跟踪流的终态帧，并在重连时使未确认回执失效。

名册只属于当前进程。运行时进程替换后，任务中心清空旧的实时作业列表并取得新基线；不会把上一个进程的作业继续显示为运行中，也不会重放。持久的会话作业注册与终态事件仍留在任务历史中，进程丢失时尚未结束的记录标为结果未确认。输出环只是实时保留的末尾，并非持久转录，因此 Host 重启无法恢复旧输出字节。任务中心也区分作业注册表不可用（`jobs: null`）与确认空名册（`jobs: []`）。

主机覆盖：`tasks-runtime.test.mjs` 检查观察前基线与无会话停止边界，`tasks_test.dart` 和 `jobs_test.dart` 检查全局导航、所属会话隔离的跟踪，以及无归属作业的跟踪和停止路由。真机验收仍待进行：从后台设置查看真实运行中的 bash 或 PTY 作业，核对进度与取消终态，再终止并重启服务，确认旧实时作业行消失、会话历史仍在。
