# Native isolated script bridge

English | [中文](native-isolated-execution-bridge.zh.md)

[`native-isolated-execution-bridge.mjs`](../runtime/native-isolated-execution-bridge.mjs) maps one internal `IsolatedExecutionRun` to five private Node-to-AgentService requests: `admit`, `execute`, `cancel`, `settle` and `release`. AgentService holds each random token in process memory while [`IsolatedScriptRunController`](../android/app/src/main/kotlin/com/minnnng/dsh_android/IsolatedScriptRunController.kt) records its run ID durably before returning admission. A reservation not started within 15 seconds is cancelled. The same run ID cannot be admitted twice, including after a receipt has been compacted. A timed-out admission is unknown and must not be retried. A stopped Agent process recovers an unfinished receipt as `INTERRUPTED_UNCONFIRMED` without launching the guest again.

The Node adapter still admits only a script with empty file and network grants. A separate App-owned manual script flow may use the native granted branch: a trusted AgentService approval callback first installs an immutable plan bound to one run ID, session ID, opaque workspace ID, program, input JSON, deadline and the controller's durable `ApprovalHandle`. The native bridge accepts narrower sets of **exact files** and exact HTTPS hosts. It may drop an approved capability category entirely, with zero calls and no broker for that category. A retained category must keep the approved call limit; lease duration must equal the approved value. The host bridge enforces the policy lease's budgets and duration, so a smaller requested value would be misleading. It never constructs authority from Node's scope. An approved policy lease and script receipt are durably admitted before checking a consumed plan's script and scope; a mismatch cancels that reservation, revokes its lease, and leaves a terminal receipt. If lease reservation fails before it returns, the bridge burns the removed plan's run ID with a durable cancelled or unconfirmed receipt when storage permits. A denied request for a pending plan cannot bypass it. File grants are exact paths, with read/search or read/search/edit actions; directory roots deliberately fail until a bounded directory-grant contract exists.

Android instrumentation checks both a successful App-approved exact-file read in a real isolated guest and rejection of a slash-suffixed directory grant before execution. The directory rejection leaves a terminal receipt; the run ID cannot be reused after bridge recreation. Directory access needs a separately reviewed bounded grant contract before it can be admitted.

The App-owned manual script flow (`AgentService.prepareManualRun`) is the current trusted producer for `prepareIsolatedScriptApproval`: its UI decision installs an exact plan before the App worker admits that run. An Agent/model request has no equivalent review producer or RPC to bind its run ID, source, scope and UI decision, and the Node adapter explicitly rejects nonempty scopes, including forged approval hints. The native manual path is not evidence of an end-to-end model-facing granted PTC feature. Denial, review expiry and Service teardown discard **unadmitted** plans without a run receipt. Such an ID may later be admitted as a new empty-scope run, but the discarded file/network grant cannot be restored; burning every pre-admission ID remains a separate lifecycle task requiring a Service teardown-safe durable design. Once a plan has been removed by `admit`, any script/scope mismatch does leave a terminal receipt, and that ID cannot be admitted again or gain a new plan, including after receipt compaction. Execution still occurs in Android's per-run isolated service and returns output only after the controller classifies guest death, Binder cleanup and durable terminal receipt publication. Cancellation waits for a terminal state before `settle` or `release`. A failed pre-execution receipt write removes the token, attempts an unconfirmed receipt and forbids replay; an unconfirmed retirement withholds output.

This bridge is an internal compute path, not a registered model tool. It does not support original Node PTC, workflow children or long-running scripts. The model-facing PTC guard remains closed until the [device and behavior gates](ptc-execution-design.md#acceptance-gates-before-enabling-model-visible-execution) pass. Host tests cover transport order, rejected Node grants, forged approval hints and approved-scope narrowing. Android instrumentation includes a real isolated UID/Binder exact-file read and rejected-plan replay checks across bridge recreation; compile or host-test success does not establish device acceptance. Network admission needs its own device execution evidence before being called verified.
