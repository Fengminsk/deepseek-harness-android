# Linux guest image handoff

English | [中文](linux-guest-image-handoff.zh.md)

`LinuxGuestBinderBinding` can be explicitly constructed by trusted App code with a `LinuxImageDescriptorBroker`. Its ordinary default remains handshake-only. There is still no Agent tool or UI entry that creates such a binding, and the ordinary APK contains no Alpine archive, PRoot executable or native supervisor.

After an `OPEN`/`HELLO` exchange for a durably admitted run, the App broker verifies the exact installed Alpine archive and issues a one-use, 15-second lease. The App passes only pinned version, ABI, byte count and SHA-256 metadata through Binder. The isolated Service checks those values against compiled constants, then returns a random call ID. The App consumes the lease once, copies the archive into sealed read-only `SharedMemory` and sends that descriptor. Every message checks the run ID and nonce; the App additionally checks Android's Binder-observed sender UID against the isolated UID, while the Service checks its Binder-observed App UID. A replay, changed metadata, expired lease, cancelled binding or writable descriptor retires the exchange.

Before the App claims the archive, the Service checks that its cache is accessible and has no stale guest rootfs. It repeats the check before extraction. The Service verifies the snapshot is read-only, then `LinuxGuestRootfsStager.stagePinned` checks the full digest, bounded archive and tar member graph before extracting into a run-specific directory below the isolated process's `cacheDir`. Regular files become owner-read-only, with the owner execute bit retained only for executable tar members; directory and file modes discard group, other and special permissions. Failed staged-tree cleanup can be retried by the same owner. These modes do not grant Android permission to execute staged files. It retains the staged data only until cancellation or Service destruction. The resulting `IMAGE_STAGED` message **only acknowledges data staging**. It does not create a terminal task receipt, prove that a process ran, or authorize publishing success. The App releases its descriptor after that acknowledgement. The rootfs staging directory is created by the isolated UID; if Android denies that write, the operation fails closed. [Android 16 isolated-app policy](https://android.googlesource.com/platform/system/sepolicy/+/android16-release/private/isolated_app_all.te) makes this cache path unlikely to work on stock devices; no device result exists yet.

The Service has no native launcher or PRoot call. An isolated process killed between filesystem publication and cleanup can leave a run-named cache directory until platform cleanup; this path must be observed and reconciled on devices before enabling a production guest. Android 10+ execution restrictions, SELinux behavior, process-tree retirement, brokered file/network access and license/distribution clearance also remain separate gates.

`LinuxGuestImageHandoffInstrumentation` checks an unpinned offer and a mismatched snapshot call ID without installing or executing an image. A valid offer may yield `isolatedStorage=preflight-denied` on stock devices; that is a recorded storage gate, not a successful stage. `LinuxGuestPinnedImageInstrumentation` is a separate opt-in positive device gate. It requires the exact source-locked Alpine archive to be supplied to a unique App cache fixture by `acceptance-linux-guest-pinned-image-device.mjs`; the archive is verified on the host and again by the App's sealed snapshot. The test requires a separate isolated UID, a pinned `IMAGE_CLAIM`, `IMAGE_STAGED` with the pinned digest, then cancellation and a second isolated offer to detect stale staging. A rejection, timeout, preflight denial or failed cleanup is a failed gate. The runner deletes only its unique App and `/data/local/tmp` fixtures. It does not bundle the archive or enable a user-facing guest.

Run only when a debug main APK, matching AndroidTest APK and local source-locked archive are ready, and device use is authorized:

```text
node apps/android/tool/acceptance-linux-guest-pinned-image-device.mjs --apk <main.apk> --test-apk <androidTest.apk> --archive <alpine-minirootfs-3.24.3-aarch64.tar.gz>
```

This gate has not run on a device. A host/AndroidTest compile does not establish Android storage or execution permission. The second offer tests ordinary cancellation and preflight visibility, not abrupt process-death recovery; that remains a separate blocker.
