# Durable Android workflow ownership

English | [中文](durable-workflow-owner.zh.md)

[`DurableWorkflowOwner`](../android/app/src/main/java/com/minnnng/dsh_android/DurableWorkflowOwner.java) is internal App-side lifecycle storage for one confined workflow run and its child IDs. The internal `IsolatedWorkflowRunNativeBridge` calls it for native admission, cancellation and terminal publication. It has no App-UID Shell fallback. Ordinary isolated scripts have a five-second cap; the App-owned private workflow guest has a separate 120-second cap. This finite bound does not establish full original workflow parity.

The original [`PtcWorkflowRun`](../../../packages/workflow/workflow-ptc/src/host.ts) owns each subagent handle through cancellation, result collection, and disposal. Android's [`IsolatedScriptRunController`](../android/app/src/main/kotlin/com/minnnng/dsh_android/IsolatedScriptRunController.kt) instead proves one isolated guest's terminal result only after Binder death, unbind, and a durable script receipt. The workflow owner joins these two requirements without treating a script result or a child result alone as a completed workflow.

The caller supplies an existing App-private parent directory and a directory fsync implementation. A canonical UUID run ID gets a new receipt file before any guest or child starts; the file is never deleted or reused. A canonical child Session UUID is generated and persisted in `RESERVED` before the child backend receives it. The caller persists `LAUNCHING` before invoking that backend. The backend launches under exactly this owner-assigned ID and confirms retirement to the native ledger before the workflow publishes completion. Its dedicated preset blocks tool execution and keeps the child inside the App process. Receipt version 2 binds this confined backend to a `WorkflowProcessLease` UUID; version 1 remains readable without inventing missing ownership. This process lease cannot attest OS descendants or external side effects.

`requestCancel` durably records `CANCEL_REQUESTED` before the caller signals a guest or any child and returns all non-retired child IDs. A concurrent completion cannot publish success after this transition. The caller confirms each child retired only after the safe backend confirms its termination and durable retirement. `complete` reads the matching `IsolatedScriptReceipt` from disk and publishes bounded output only when it says `COMPLETED`, every child is retired, and the workflow still says `ADMITTED`. `confirmCancelled` additionally requires a `CANCELLED` guest receipt. `confirmFailed` requires a confirmed `ERROR`, `TIMED_OUT`, or `WORKER_DIED` guest receipt and retired children. `markUnconfirmed` preserves the run and its pending child identities when retirement cannot be proven. None of these operations accepts a caller-supplied success flag or unconfirmed output.

On process startup, `recoverInterrupted` must run before accepting new workflow work. The process lease holds one App-private OS file lock for the whole JVM lifetime; there is no logical close API. Recovery preserves a known live owner's active receipt. When the old lease lock can be acquired, Android has released that process's lock, so its recorded in-process children can become `RETIRED`. The interrupted run remains `INTERRUPTED_UNCONFIRMED` with no output: child termination does not prove task completion or undo effects. A missing lease, a still-held lock, or a legacy receipt without a lease cannot establish termination. Those child IDs remain pending across repeated recovery and block new admission until confirmed cleanup. Recovery never replays a script or launches a child. A torn or malformed receipt remains in place, prevents reuse of its UUID, and makes reconciliation fail closed; an operator must inspect it before new workflow admission. Existing completed, failed and cancelled receipts remain unchanged.

`requestCancel` persists cancellation and publishes its in-process signal under the same owner lock, so a callback cannot observe the new durable state before the signal. An explicit cancellation interruption is ordinary control flow; it is not itself proof of uncertain effects. Callback retirement still joins both the callback worker and the Node child port before returning a confirmed cancellation. Other callback failures or an unjoined close remain unconfirmed.

The Session ID remains the original 1–128 character ASCII identifier (`[A-Za-z0-9][A-Za-z0-9._:-]{0,127}`), including Android's `android-…` form. It is not replaced by a generated UUID. Run IDs, nonces and workspace IDs still require canonical UUIDs. This preserves the original Session event history and approval ownership.

Each operation takes an OS file lock and an in-process monitor, reads the current receipt, and atomically replaces a bounded checksummed snapshot followed by directory sync. Locking prevents two App processes from both publishing a transition. The owner requires startup reconciliation before every mutating operation. It retains at most 4,096 run receipts and never prunes their IDs; exhausted capacity refuses new work. An unpublished replacement temp is not a run receipt and cannot erase its already admitted ID. File and directory sync failures stop the call; they may leave a new ID consumed or an outcome uncertain. A failed admission sync or receipt replacement revokes that owner's reconciliation state, so it refuses further mutations until `recoverInterrupted` runs and marks unfinished runs unconfirmed. The owner does not attest child-side effects, retroactively undo them, or prove that an Android process killed outside the App has stopped descendants. Those guarantees require a confined child backend and device validation.

Host acceptance: `node apps/android/tool/acceptance-durable-workflow-owner.mjs` compiles Java and checks ownership, cancellation, a separate JVM's restart recovery, no replay, a clean completion receipt, corrupted-file refusal, and injected directory-sync failure. It also kills a real child JVM while its lease is held, proves live-owner preservation and stopped-owner retirement, and checks v1 receipt compatibility and missing/foreign lease refusal. The ordinary host test uses a no-op directory-sync adapter; Android filesystem durability and App integration still require the separate [device acceptance](native-workflow-process-death-device-acceptance.md).
A V8 script receipt may be `COMPLETED` even when the workflow DSL returns `stopReason: error`. The native owner now records that DSL outcome as `FAILED` with no output; an unknown reported stop reason stays `INTERRUPTED_UNCONFIRMED`. The private Node caller joins concurrent Abort cancellation before settlement, validates the DSL result, and releases only after both the native terminal receipt and local child retirement are confirmed. The model-facing route remains disabled until device acceptance.
The native terminal classifier requires the exact bounded DSL envelope: `value`, `stopReason` and integer `agentsStarted`, plus the structured error fields for failure. Missing, malformed or unknown outcomes remain unconfirmed, even when V8 itself completed.

The trusted App-private `startBackgroundDsl` path registers one job in the original `ctx.jobs` registry with the exact parent Agent as owner. Job cancellation and owner disposal abort the run and wait for native cancellation, child retirement, and settlement before the producer reports a terminal job outcome. Only a confirmed workflow completion exposes a result; an unconfirmed native retirement fails the job and leaves the Session run open for review. The jobs registry is process-local. After process death it does not resume the job or guest. `workflow.inspect` reads the persisted Session events and, for an open run, the native receipt through `native.workflow.inspect`; an interrupted receipt and pending child count remain visible without replay or fabricated `run-end`. A native terminal receipt without a flushed Session terminal event is reported as unconfirmed rather than success.

The App-private background entry is not wired to the model-facing `run_in_background` argument. That argument and the original workflow tool remain disabled. Enabling them requires a trusted production registration path, Android device tests for App process death and child cleanup, and general PTC parity.
