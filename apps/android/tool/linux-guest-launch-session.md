# Native Linux guest run accounting

English | [中文](linux-guest-launch-session.zh.md)

`LinuxGuestLaunchSession` is an App-side accounting component for a proposed Alpine/PRoot run. It is not connected to a launcher, model tool, or the image verifier. The current APK contains no PRoot ELF or Alpine rootfs; the source audit still reports `distributionApproved: false`. Constructing a session therefore does not make Linux commands available.

The trusted App must durably admit a run through `IsolatedExecutionPolicyOwner` and project its live `LinuxGuestSandboxPolicy`. The session binds that run ID to the pinned image SHA-256, launcher and loader digests, a monotonic deadline, one Binder-observed guest UID, bounded output, and outstanding App-broker calls. `LinuxGuestLaunchSession.admitInstalled` now invokes `LinuxGuestInstalledElfVerifier.verify` for the two fixed arm64 ELF candidates under `ApplicationInfo.nativeLibraryDir`: it rejects absent, linked, writable, oversized, wrong-architecture, changed, or digest-mismatched files before creating the accounting session. The class does not itself connect the future launcher; the existing raw-digest constructor remains a dormant test/accounting seam and is not a secure executable admission point on its own. The native supervisor must reverify the same pinned content through its opened descriptors at launch, since a Java preflight cannot prevent later replacement. The caller must bind an Android `isolatedProcess` service and use `Message.sendingUid` as `sendingUid`; a guest-provided integer alone does not establish isolation.

File and HTTPS requests are prechecked against the live scope, then counted until the actual App brokers return audited settlements. This component does not open a file, mount a directory, or create a socket. The App must read `DSH_TRACE_V1` bytes directly from an OS-owned pipe while PRoot runs and pass real pipe EOF and tracer process exit to the session. A guest Binder payload is not process evidence. A successful result is publishable only after tracee retirement, all broker calls settle, output stays within its limit, the lease remains live, and the App has durably recorded the terminal result. Cancellation, timeout, revocation, malformed trace, wrong UID, and missing audit settlement deny success.

Run host-only lifecycle checks with `node apps/android/tool/acceptance-linux-guest-launch-session.mjs` and installed-ELF checks with `node apps/android/tool/acceptance-linux-guest-installed-elf.mjs`. These checks use synthetic Binder, trace, and ELF inputs. Device validation still needs executable packaging and distribution review, isolated UID and file/network denial evidence, real PRoot process-tree retirement, cancellation, background execution, and upgrade recovery. Do not expose a general Linux Shell before those gates pass.
