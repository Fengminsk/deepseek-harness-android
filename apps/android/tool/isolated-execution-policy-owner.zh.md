# App 持有的隔离执行策略

[English](isolated-execution-policy-owner.md) | 中文

[`IsolatedExecutionPolicyOwner`](../android/app/src/main/java/com/minnnng/dsh_android/IsolatedExecutionPolicyOwner.java) 为内部隔离脚本运行器及未来 PTC 或工作流提供者保存不可变策略快照。新建策略持有者从版本 1 开始，没有文件范围，也没有网络主机。所有者与会话 ID 固定；每次运行使用规范 UUID、有界租期、调用额度、授予文件权限时由 App 确认的准确工作区根目录、相对可读写范围，以及准确的 HTTPS 主机名。文件与网络策略相互独立：只授予网络时不需要工作区。客体只能收到运行 ID 和不透明的代理句柄，不能收到根目录路径。此类尚无面向模型的调用方，也不约束现有 App UID Shell、DSH 文件工具或插件。

受信任的 App 必须先确认用户选择，才能建立非空权限范围。此类通过 `IsolatedCapabilityBroker.SandboxPolicy` 校验路径，并通过 `IsolatedNetworkBroker.Policy` 校验主机名；所选工作区还必须解析到已有的 App 私有根目录内。文件代理仍须逐次执行基于目录描述符且不跟随符号链接的操作，因为策略建立时的路径检查无法阻止后续文件系统变更。子运行只能缩小父运行的路径范围、主机集合、调用额度和租期；嵌套最多 16 层，策略持有者最多保留 128 个有效租期。替换现行策略必须保持所有者与会话 ID 不变，且版本恰好增加 1。替换操作在调用撤销钩子或 App 的 `DurableTransition` 记录变更前，先关闭接纳并移除全部有效租期；重入钩子不能用旧版本再接纳运行。如果记录失败，策略持有者拒绝之后的所有接纳，旧租期也不能继续使用。回调可能写入磁盘，因此 App 必须在非主线程执行替换。

`IsolatedScriptRunController.newPolicyOwner` 现已打开持久化审批存储器，并把 `DurableAdmission.reserve` 接到一次性脚本回执存储。带文件或网络能力的脚本运行必须同时提供这个控制器签发的策略所有者与宿主策略。控制器只调用一次策略接纳，核对同一运行 ID 已持久接纳，不会再次接纳回执。预留写入失败时，策略持有者会撤销已有租期并拒绝继续接纳，直到从持久状态恢复后新建持有者。绑定客体前，会拒绝所有者、工作区、授权或文件调用额度超过有效租期的策略。撤销或策略版本变化会拒绝后续文件调用，阻止发布已完成的结果；最终回执发布与策略替换串行。正在进行的编辑仍由文件代理和每次运行的发布栅栏收尾；取消与发布重叠时结果为未确认。运行结束后控制器撤销租期。纯 JavaScript 路径仍直接使用回执存储，没有 host 对象。

策略持有者不会恢复运行中的权限范围。App 进程死亡后，全部租期消失，脚本回执恢复会把未完成运行标为结果不确定，不能重放。[审批历史存储器](isolated-execution-approval-store.zh.md)持久记录策略版本，并在重启时撤销已记录的授权。控制器的授予 API 把经过审阅的范围绑定到一个运行 ID；App 现有内部待审界面与前台原生确认通道，但尚无生产代码为此界面准备脚本请求。客体仍须在 App 回复 Binder 死亡时退出；策略持有者本身无法停止进程，也无法撤销已提交的文件或网络副作用。现有 App UID Shell、DSH 文件工具与插件仍在此策略范围之外；尚未启用面向模型的 PTC 或工作流工具。

运行 `node apps/android/tool/acceptance-isolated-execution-policy.mjs` 可以检查默认拒绝、不可变权限范围、预留回调的调用顺序和失败处理、子运行权限收窄、版本失效、撤销、失败关闭、路径与主机校验，以及重启后不恢复授权。Android 仪表测试还覆盖单次运行的授权绑定、文件策略的重放和撤销，但目前只完成编译，尚未在手机上运行。宿主检查也不能证明 Android UID 隔离、Binder 死亡、SAF 行为或真实审批记录的持久性。策略用于模型编写的任务之前，还须在普通无 Root 设备上完成 App 审批全链路验收。
