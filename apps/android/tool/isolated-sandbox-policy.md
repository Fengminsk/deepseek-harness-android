# Android isolated sandbox policy projection

English | [中文](isolated-sandbox-policy.zh.md)

The original DSH `sandboxPolicy.resolve()` defaults to `read-only` and resolves `workspace-write` against a Session workspace. Android model-authored PTC cannot safely use its App-UID Node process as that workspace sandbox. [`isolated-sandbox-policy.mjs`](../runtime/isolated-sandbox-policy.mjs) projects an **already App-selected capability scope** into a smaller Android policy; it does not approve that scope, admit a run or enforce file and network operations. The native policy owner, isolated UID guest, file broker and HTTPS broker remain the enforcing components. The model-facing PTC and workflow entries remain disabled.

`projectIsolatedSandboxPolicy({approvedScope, mode?, networkMode?}, parent?)` defaults to `read-only` files and `deny` network. Readable paths, if selected by the App, remain exact relative file or directory scopes; the guest still receives only App-issued exact-file handles. `workspace-write` permits only the `approvedScope.writablePaths` contained in its readable scope. Edits to `.git`, `.agents`, `.codex` and `.aws` path segments are denied even through a broader directory grant. Network access is independent: `allow-listed-https` can use only `approvedScope.exactHosts` and its network-call budget. An omitted or denied network mode cannot carry host grants. There is no `danger-full-access`, unrestricted network mode, arbitrary path, ambient credential, subprocess or Shell grant in this policy.

The decision object accepts only own data properties. The App must obtain `approvedScope` from its trusted approval owner, bind it to the correct Session and run, and freeze the selected grant before native admission. This JavaScript function cannot prove that a caller obtained human approval; passing a fabricated scope to it does not grant native authority. `requireIsolatedSandboxPolicy` accepts only a policy projected by this module before a model draft is prepared. A projected child must refer to a live policy returned by this module, cannot change owner, Session, workspace or version, and may only narrow modes, relative paths, exact hosts, budgets and lease. Native admission and every file/network call must independently check the same immutable scope. A changed policy or interrupted run revokes grants; a retry needs a new approval and run identity.

Host validation: `node --test apps/android/tool/isolated-sandbox-policy.test.mjs apps/android/tool/isolated-execution-contract.test.mjs`. These tests cover default denial, separate write/network selection, forged decision fields and accessors, copied immutable scope and child attenuation. They do not establish Android Binder identity, device filesystem confinement, DNS/TLS routing, user approval or process-death recovery.
