# Android completion receipt crash acceptance

[中文](task-completion-device-acceptance.zh.md) | English

`TaskCompletionCrashInstrumentation` runs in the App's `:agent` process with generated Session IDs. Its hold phase sends a synthetic successful-completion signal through `TaskCompletionNotifications`, waits until the end-sequence watermark and matching pending receipt are committed, and blocks the main thread before the notification can display. The runner's next command force-stops the App, then awaits the held ADB client's actual close and verifies that no App, test or isolated-service process remains. A new Agent process must deliver one matching notification, remove the committed receipt, retain the watermark, and suppress stale and malformed synthetic receipts. The final native cleanup removes only this token's generated preference keys and notification. No model request, account change or real Session creation is involved.

Inspect an App and AndroidTest pair from the same source and signer without a phone:

```sh
node apps/android/tool/acceptance-task-completion-device.mjs --apk <app.apk> --test-apk <androidTest.apk> --preflight-only
```

Device execution requires an authorized existing installation, completion notifications already enabled, and a phone that is locked and noninteractive. Supply every argument below and a new report path. The runner checks the local package, signer and instrumentation identity, then compares both installed base APK SHA-256 values with the supplied artifacts. Missing, changed or split installations are rejected. `--installed-only` never installs, downgrades, clears data, grants permissions, launches an Activity or sends display/lock input. `--allow-existing` authorizes interruption of this installation; full process-name checks must find no App or test processes before admission and immediately before hold.

```sh
node apps/android/tool/acceptance-task-completion-device.mjs --adb <adb-path> --serial <adb-serial> --apk <exact-installed-app.apk> --test-apk <exact-installed-test.apk> --allow-existing --installed-only --no-wake --report <new-report.json>
```

`runTaskCompletionEntry(args, { signal })` owns the report and ADB adapter; `runTaskCompletionCrashAcceptance(io, options)` owns hold, forced death, verification and retirement. The [screen-protection owner](device-screen-protection.md) can await the entry in-process with its cancellation signal. The standalone CLI handles SIGINT/SIGTERM through the same path. Locked/noninteractive checks are not physical-panel evidence: retain the outer owner's panel observations and confirmed device retirement. Neither an ended instrumentation command nor a requested client kill establishes retirement.

Each ordinary ADB command is bounded by eight seconds, hold readiness by 20 seconds, and verify or token cleanup by 30 seconds; client result settlement may require up to 3.5 additional seconds. Once committed hold readiness appears, no further observation RPC delays force-stop. Closing a held client is awaited for at most 20 seconds. Cancellation or failure uses an independent cleanup scope to force-stop both App and test packages, stop and join every owned ADB child, and observe complete App/test/isolated-service process names for up to 20 seconds plus bounded command latency. A missing close, failed force-stop or surviving process prevents retirement confirmation and a pass. Work cancellation never cancels this cleanup.

Native token cleanup runs only after successful verification, including if cancellation arrives afterward. Failed verification cannot bypass the native requirement that the receipt has been acknowledged; its token is retained in the report with `syntheticStateMayRemain: true`. Cleanup failure invalidates success. Reports retain the generated token, exact artifact digests, bounded phase results, failure stages/types and separate host/device retirement facts; they omit arbitrary tool output, notification text and account data. The report is reserved exclusively before work and written after cleanup; an existing path is never overwritten. If persistence fails, the thrown error and fallback diagnostic retain the sanitized result. Hard host termination or lost USB can still leave synthetic state or unknown retirement; preserve that token for scoped investigation rather than clearing user data.

`node --test apps/android/tool/acceptance-task-completion-device.test.mjs` checks exact installed identity, locked and idle admission, immediate force-stop ordering, delayed close, cancellation, failed native verification/cleanup, orphan detection, report reservation and a real host child termination. These host checks do not establish device delivery. The device result below proves synthetic receipt delivery after one forced Agent-process death, not a real model task, Session replay behavior, notice interaction or the complete background-task lifecycle. The [account-task acceptance](agent-service-task-device.md) owns its separate real-account evidence.

## Build 116 r35 device result

`.cache/android/completion-crash-116-r35-result-20261028.json` records a pass; the companion screen report replaces `result` with `screen`. This run checked the existing installation without reinstalling it: the production App SHA-256 remained `5cd11e06ab70a170235971f7a0140c982db992acf2c3c368066752e7089c7b41`, and AndroidTest SHA-256 was `dc06f94ba4fc2861f8e861609e4d52350afb64127b208f5e36169eb2a2b6a926`. Hold PID 24363 was force-stopped, verification ran in PID 24431, and cleanup ran in PID 24496. The matching notice existed, invalid notices were absent, receipts were cleared, and this token's synthetic state cleanup passed.

The report confirms both package force-stops, closure of all owned host clients and device-process retirement; `cleanupFailures` is empty and `syntheticStateMayRemain` is false. The outer owner recorded four samples with both OLED panels Off and restored screen control while noninteractive. No wake operation was used, and the entry required an already locked/noninteractive phone. These remain bounded samples, not continuous screen observation or prolonged background survival, and do not prove real-task replay or recovery after process death.
