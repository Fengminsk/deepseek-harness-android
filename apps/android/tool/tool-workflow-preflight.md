# Android model workflow preflight

English | [中文](tool-workflow-preflight.zh.md)

`prepareModelWorkflow` in [`tool-workflow-preflight.mjs`](../runtime/tool-workflow-preflight.mjs) copies the original `workflow` tool shape (`script`, `meta`, optional JSON `args`) into a bounded host-owned request. The App supplies the Session, random run ID, issued sandbox policy, deadline and child budgets; model arguments cannot set these fields. The preflight parses a plain JavaScript async body without running it, rejects TypeScript and malformed syntax, and rejects background execution until a durable job owner exists. It currently requires a read-only, no-network policy with no file grants. A failed or uncertain native receipt never exposes an output value.

**This does not register a model tool.** `runModelWorkflow` and `modelAdmission.run()` remain fail-closed. The original [`tool-workflow`](../../../packages/workflow/tool-workflow/src/index.ts) runs a JavaScript script with `agent`, `parallel`, `pipeline`, progress, cancellation and optional background jobs. Android has an App-private native workflow runner with bounded guest hooks, confined child Agent backend and original parent Session run/member records. Its reviewed admission ticket now connects to that runner through an explicit App-private `executePrivate()` path. The ticket is bound to the exact live Agent, ToolRuntime registration and Session; it is consumed before native admission, so a failed admission cannot be replayed. Cancellation, definition replacement and owner disposal revoke it. The runner has narrower budgets and a finite 120-second private guest deadline; ordinary isolated scripts remain capped at five seconds. This private path is not a model-facing tool.

The remaining integration must bind a first-party model tool to this reviewed caller only after the narrow private runner supports useful inference durations, persistent background ownership and cold-start reconciliation of incomplete run records. General Node/TypeScript PTC still needs its own confined Android provider; the V8 workflow DSL is narrower. Android device acceptance must cover child isolation, progress, cancellation, process death and upgrade before enabling the model tool.

Host checks: `node --test apps/android/tool/tool-workflow-preflight.test.mjs` and `node --import tsx --test apps/android/tool/model-workflow-admission.test.mjs`.
