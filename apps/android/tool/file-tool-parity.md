# Android Agent file tools: authority and page contract

The original DSH `read`, `read_image`, `write` and `edit` use the Android `AndroidFileSystem` provider. The model file guard confines `read`, `read_image`, `write`, `edit` and `present` to the boot-pinned App workspace. `write` also uses the provider's `workspace-write` mutation policy, but the general policy's temporary-directory exception does not grant model `write` access to App-private temporary files; internal App services retain that exception. The [keyless ToolRuntime projection](expected/model-file-write-guard.expected.json) records successful workspace writes and both guard and provider denials.

Original `glob` and `grep` execute packaged ripgrep through the guarded subprocess seam. Relative paths resolve from the pinned Session working directory. These paths are ordinary files, never `content://` URIs. `glob` can report matching workspace file paths; `android_files/list` lists directories under an explicit SAF grant. The original `str_replace_editor` directory `view` remains denied: its two-level walk follows a child symlink and can disclose App-private names, as the [keyless ToolRuntime projection](expected/model-directory-guard.expected.json) records. `AndroidFileSystem.listDir` also refuses model-scope enumeration at the operation itself, including when a checked file becomes a directory before the original tool body runs; internal App listings remain available. This is a closed route, not an equivalent replacement for the original directory view. Model-scoped stat/read operations re-resolve retained targets at observation time; lazy text streams re-resolve when consumed. These trusted-code checks narrow stale-target exposure but cannot provide kernel isolation from another process with the same UID replacing a parent directory between validation and the filesystem system call.

A persisted Storage Access Framework (SAF) grant uses the separate `android_files` model tool: `roots`, `list`, `read`, `read_image` and literal `search`. `read` returns bounded UTF-8 pages. The first page establishes a snapshot `version`; every nonzero-offset model continuation must return that version. The Node adapter rejects a changed version, a page whose `offset` differs from the requested position, an invalid or backward `nextOffset`, a page over 256 KiB, a decoded string whose UTF-8 byte count differs from the reported span, and a truncated page that makes no progress. This prevents the Agent from silently joining missing or repeated text into a summary. An empty final page at EOF is valid. The App's reader may explicitly restart at offset zero after a connection change.

The SAF grant does not authorize the ordinary workspace `read_image` tool. `android_files/read_image` takes the opaque grant ID and a relative path (empty for a single-file grant), then returns a durable model image block for PNG, JPEG, WebP or GIF. It checks the active model's image input capability and attachment policy before native I/O. Native reads resolve only a persisted grant, reject virtual documents and declared oversize files, stream no more than 20 MiB, and compare two complete reads plus metadata before returning bytes. Node verifies the SHA-256, canonical base64 and image signature before committing an attachment. The image bytes are not included in the tool result or conversation text. Abort sends a native cancel request; revoking the grant also cancels active reads. PDFs and other binary formats still require a separate model ingestion route. No Android device or third-party SAF provider was exercised by this host test; grant persistence, revocation and provider-specific behavior still need device acceptance.

The App-private workspace text reader checks each continuation response against the requested version, root, total byte count and byte range before replacing the visible page. A mismatched or malformed response leaves the last confirmed page visible and retryable; an explicit reconnection refresh may establish a new version without joining it to earlier pages.
