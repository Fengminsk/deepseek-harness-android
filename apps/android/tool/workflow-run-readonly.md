# Android 历史工作流运行记录契约

原版 `ui-workflow-run` 只读取调用方 Session 中持久化的四类 `tool-workflow/*` 事件：`run-start` 创建一条运行记录；`agent-start` 增加成员并保留首现阶段顺序；`agent-end` 更新该成员状态；`run-end` 决定运行的最终状态。界面展开运行、阶段后仅显示名称、数量和状态，不显示脚本、输出、错误详情、日志、用量或控制操作。普通 Step/Turn 结束不能推断后台运行已结束；只有所属 Turn 明确以 `interrupted` 或 `forked` 结束，且运行没有终止事件时，才标为已中断。

Android 对相同的原始事件做只读回放。历史分页若先收到更新、尚无 `run-start`，不生成占位运行；补入更早页面后重放并显示。实时新增事件增量处理，空白流帧不会重算。记录按 `run-start` 事件序号插入会话阅读流，四类事件不会被误认为未知调试消息。缺失阶段与空字符串阶段保留不同身份。完成后默认收起，运行中、失败、已取消、已中断默认展开；新的异常边或阶段新一轮成员会重新展开。

本入口不调用或启用 Android 当前禁用的 `ptc-runtime`、`workflow-ptc`、`tool-workflow`，也不伪造可执行的工作流。Android 目前不能创建新的工作流记录；只有已存在且可由当前 Session 历史读取的记录可见。子会话入口仅在当前父会话的原版目录实时确认其仍挂载、运行且地址匹配时出现；点击时再次读取子会话自身描述，校验父子身份、运行状态和连接代际。旧事件或失效状态不能单独授权跳转。没有真机验证时，仅能声明主机上的投影、Flutter 组件和会话流集成测试通过。
