# Background completion notice recovery acceptance

[中文](task-completion-recovery-acceptance.zh.md) | English

This is a reference for notification delivery after the Android Agent process exits. A completion receipt and its end-sequence watermark are committed together when a live driver reports successful completion. Recovery reads only committed receipts whose sequence matches the watermark. It may display a notification; it never restarts a task or infers success from an idle Session. Invalid and stale receipts are removed on the notification writer, and valid receipts reach the main thread in batches of at most eight. A delivery failure, including notification permission changing between the check and Android's post, leaves its receipt available to a later Service generation. A receipt is acknowledged after Android accepts the post or when the notice was deliberately suppressed; acknowledgement never changes the Session result.

When a Service destruction callback arrives after Node admission, it records an interrupted runtime before optional resource cleanup and requires the dedicated process to exit even if cleanup fails. Cold recovery treats an orphaned process lease as an interruption when Android kills the process without a callback. Neither path claims an unfinished task succeeded.

Run `node apps/android/tool/acceptance-task-completion.mjs` from the repository root. The host tests cover claim deduplication, visible-session suppression, delayed persistence, shutdown drain, receipt encoding, and recovery snapshot filtering. They cannot prove Android notification permission behavior, actual Service destruction, foreground-service timeout, or process scheduling.

For device acceptance when a phone is available, record the APK hash, Android version, notification permission, session ID, and last committed end sequence. Complete a task while viewing another screen, then verify one short notification opens that Session. Complete another task while viewing its Session and verify that no duplicate alert appears. After a completed turn, terminate only the Agent process immediately after the receipt commit and reopen the app; verify that at most one pending notice appears, that its Session contains the original result, and that no model or tool call runs again. Repeat with notifications disabled, with an interrupted task, and with network disconnected before reopening. Check the Session and task state before attributing any absence of a notice to recovery.

A host pass does not satisfy the device acceptance above. In particular, Android may kill the process without calling `Service.onDestroy`, and the OS may reject or defer notifications despite a committed receipt. Do not report an interrupted task as successful or automatically retry an unknown tool outcome.
