# Linux guest storage on stock Android

English | [中文](linux-guest-storage-options.zh.md)

This reference applies to an ordinary, non-rooted app with an `isolatedProcess` guest. It does not claim that the current PRoot candidate runs. Android describes an isolated Service as having no permissions of its own. AOSP's Android 16 policy allows an isolated process to use already open app-data file descriptors received over IPC, but prohibits it from opening app-data files by path or creating ordinary network sockets. App-private `cacheDir` therefore cannot be assumed to hold a rootfs that the isolated process can create and traverse. The device must determine the exact failure point; the current staging preflight rejects unavailable storage. [Service declaration](https://developer.android.com/guide/topics/manifest/service-element), [AOSP isolated-app rules](https://android.googlesource.com/platform/system/sepolicy/+/android16-release/private/isolated_app_all.te).

| Candidate | What the isolated process receives | Remaining obstacle |
| --- | --- | --- |
| APK-packaged native tools | Fixed, reviewed Bionic-compatible executables from the installed app code location | Confirm package-manager extraction, `execve`, library loading, cancellation and every descendant on a device; keep the command catalog and App brokers bounded. |
| APK asset or packaged Alpine tar | Read-only bytes through the APK or a sealed snapshot | A tar or ZIP is not a filesystem tree for PRoot's `--rootfs=path`; unpacking into App home cannot be assumed available to an isolated UID. |
| Binder-passed file or directory FD | Access to the already open object | The debug device probe tests child `openat` against a transferred directory FD. Until that device result is known, the FD cannot be treated as a traversable PRoot root directory; one archive FD is not an FHS namespace. |
| `SharedMemory` or memfd | Bounded bytes without App-private pathname access | A sealed data mapping is suitable for verification, not a directory hierarchy or an executable guest program. The current snapshot removes write and execute mappings. |
| App-UID PRoot | Ordinary App-owned rootfs paths | The guest inherits App-private file and credential access unless a separate, independently proven OS confinement mechanism exists. PRoot's path translation is not that mechanism. |

The near-term execution route is a fixed catalog of APK-packaged native tools in the isolated UID, with no direct workspace mount or socket, plus App-mediated file and HTTPS operations. SHA-256, byte count and line count use one APK-packaged Bionic executable with fixed mode arguments and bounded stdin; other fixed commands still use Android system tools. This is a utility catalog, not an Alpine namespace. Android directs apps targeting API 29+ to execute code embedded in the APK rather than writable App home; packaging native libraries as extractable files is a separate build setting and must be verified in the final APK and on-device. [Android execution restriction](https://developer.android.com/about/versions/10/behavior-changes-10#execute-permission), [native-library packaging](https://developer.android.com/guide/topics/manifest/application-element), [AOSP app-code policy](https://android.googlesource.com/platform/system/sepolicy/+/android16-release/private/app.te).

A full Alpine guest would require a separately reviewed filesystem virtualization layer that supplies PRoot's path, directory, metadata, loader and execution operations from brokered bytes, or another OS-backed isolated storage mechanism proven on the target device. Existing PRoot expects a real host path for `--rootfs` and uses `ptrace` to rewrite paths; its binds do not grant isolation from host resources. No such virtual filesystem is implemented here. [PRoot manual](https://github.com/termux/proot/blob/master/doc/proot/manual.txt).

Device acceptance must observe the guest UID, executable package path and digest, denial of App-private files and direct sockets, allowed broker calls, cancellation of descendants, package upgrades and abrupt Service death. The [synthetic storage device probe](acceptance-linux-guest-storage-device.md) also distinguishes use of a passed file FD from child-path traversal through a passed directory FD. It records storage and execution observations without claiming a Linux run. A storage preflight failure remains a rejected run; it must never fall back to App-UID command execution.
