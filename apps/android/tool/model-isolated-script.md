# Android model script adapter boundary

This is an **unregistered adapter draft**, not the original DSH `run_code` tool. The original tool in `packages/core/tools/src/ptc.ts` accepts a TypeScript async function body and injects scoped `tools.*` bindings. `workflow-ptc` also requires a TypeScript runtime. The Android host erases erasable TypeScript while preserving source positions for the isolated V8 JavaScript function-body entry. The native Binder tool callback route exists, but original tool bindings have no production model caller or device acceptance. Android `ptc-runtime`, `workflow-ptc` and `tool-workflow` remain disabled.

`prepareModelIsolatedScript` accepts only `{language: "typescript-function-body", code, description}` from an untrusted future model tool. The trusted host supplies Session identity, deadline and an issued `IsolatedSandboxPolicy`; the adapter generates a fresh run ID. The host policy defaults to read-only files and denied network, and can describe App-approved writable paths or exact HTTPS hosts independently. All required model and host fields must be own data properties; missing fields never read inherited accessors. Model-supplied `runId`, `sessionId`, `sandboxPolicy`, path, host, escalation and timeout fields are rejected. A fabricated host policy is also rejected. The draft is immutable and does not authorize effects. Native admission still refuses nonempty scopes on this adapter, and the model-facing execution gate remains closed; the App must connect its trusted approval producer and prove native enforcement before enabling it.

`runModelIsolatedScript` always invokes the existing `ANDROID_PTC_UNAVAILABLE` gate before touching a bridge. Repeated calls cannot admit or replay a run. `projectModelIsolatedScriptReceipt` exposes a value only from a matching durable `COMPLETED` receipt; cancellation, timeout and uncertain recovery cannot leak output. The latter projection is a host contract test, not Android Binder/JNI evidence.

`startAppOwnedModelIsolatedScript` is an internal App-host executor behind that closed gate. It consumes one genuine draft exactly once, requires the App-issued native bridge and callback manager, and admits the compiled body through `native.isolated.admit`. The App binds a selected pure/read-only ToolRuntime allowlist before guest execution. Each nested call is authorized and written to the parent Session audit before its result returns to the guest; cancellation joins the native stop and callback retirement. The native adapter rejects every nonempty file, write or network scope before admission. Host tests exercise this Android RPC path; it is not registered as a model tool and does not substitute for device UID, Binder and process-death evidence.

Validation: `node --test apps/android/tool/model-isolated-script.test.mjs apps/android/tool/app-owned-model-ptc.test.mjs`. Tests cover ownership, forged grant fields and prototype accessors, TypeScript format, trusted policy projection, closed-gate no-dispatch, App-owned native admission and sub-dispatch, one-use drafts, cancellation, and output withholding. Enabling the tool requires native function-body admission, nested tool-binding parity, App policy review, UID/Binder/network/file/process-death tests on a device and an explicit product decision.
