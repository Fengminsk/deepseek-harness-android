# Pocket Harness for Android

[English](README.md) | 中文

## 概述

本目录包含 Flutter App、Kotlin 前台服务和内嵌 ARM64 Node 运行时。当前产物是适用于 Android 9 及以上版本的开发预览；运行时与 App/Web 集成仍需真机验收。

## 构建预览版

使用 Windows PowerShell 7、Node 24、仓库指定的 pnpm、JDK 17、Android SDK 36、NDK 28.2.13676358 和 CMake 3.22.1。Flutter 与原生依赖版本固定在 [tool/runtime-lock.json](tool/runtime-lock.json)。先将指定 Flutter 版本放到仓库忽略的 `.cache/flutter` 目录，并配置 Android SDK。

完成 `pnpm install` 后，在仓库根目录执行以下命令。deploy 命令创建新的暂存目录；仅修改 App 时可保留该目录复用。依赖锁文件变化后应重新部署暂存目录。后面的 install 用于恢复 pnpm deploy 后的工作区开发依赖。

```powershell
pnpm.cmd run build:artifacts
pnpm.cmd --filter dsh-python-runtime-closure deploy --legacy --prod --config.allow-unused-patches=true --config.node-linker=hoisted --config.auto-install-peers=false --config.link-workspace-packages=true --config.hoist-workspace-packages=false .cache/android/runtime-bundle
pnpm.cmd install --offline --frozen-lockfile --prod=false --ignore-scripts
node node_modules/tsx/dist/cli.mjs apps/android/tool/stage-runtime.ts
./apps/android/tool/prepare-native.ps1
node apps/android/tool/smoke-runtime.mjs
./apps/android/tool/pack-runtime.ps1
```

原生准备脚本默认使用 `http://127.0.0.1:7897`；可通过 `-Proxy` 指定其他代理。脚本校验 Node 压缩包的哈希，以及 Android require-builtin 插件的源码版本。暂存运行时冒烟测试在电脑上执行，不代表 Android 兼容性已通过。

在 `apps/android` 执行以下命令。APK 输出到 `build/app/outputs/flutter-apk/app-debug.apk`，使用开发签名。如果本地网络需要代理，请配置 Gradle 的 HTTP/HTTPS 代理。

```powershell
../../.cache/flutter/bin/flutter.bat pub get
../../.cache/flutter/bin/flutter.bat analyze --no-pub
../../.cache/flutter/bin/flutter.bat test --no-pub
../../.cache/flutter/bin/flutter.bat build apk --debug --target-platform android-arm64 --no-pub
```

## 运行时与存储

前台服务在独立的 Android 私有进程中持有一个 Node 实例。Flutter 经 Binder 和专用本地套接字上的 JSON-RPC 通信，不使用本机 HTTP 服务。标准输出与错误写入私有运行日志，与协议通道分离。较大的 Binder 响应通过只读共享内存传递。打包运行时由名为 `android` 的 dsh profile 启动，工作区和会话存放在应用私有目录。API 凭据使用 Android Keystore 支持的加密存储；授权文档目录使用 Storage Access Framework 的持久授权。

Android 附件、会话和 ZIP 发布会先完整复制并同步临时文件，再通过原生 `renameat2(RENAME_NOREPLACE)` 发布，避开部分设备禁止的硬链接，同时不覆盖已有目标、不暴露未写完的文件。原版 DSH 的摘要、碰撞校验、租约和追加行为仍由原服务负责；其他平台保留已有发布实现。

Web 偏好与浏览器可修改的运行时设置分开。App 控制监听、范围和端口；网络回调选择明确的 Wi-Fi／以太网 IPv4 地址，局域网地址不可用时显示等待。凭证轮换保留 Agent 上下文。这些生命周期行为仍需 App/Web 共同操作的真机测试。

Android Shell 工具通过原版 DSH 工具执行流程逐条请求授权，仅 `allowed-once` 允许执行；拒绝、取消及 `never` 授权策略都不会放行。命令使用应用现有 UID 和 Android 权限执行，不提供只读或仅工作区的操作系统沙箱。逐条审批是 Android 工具的规则，不代表桌面版默认策略。Root、ADB 控制、开机自启动和离线模型推理尚未实现。

Shell 超时结果区分终止请求与命令已结束后才处理的截止定时器。截止时间会持续生效到输出管道关闭，因为 Shell 成功退出后仍可能有存活的后代占用管道。无法通过进程观察确认结果时，工具返回 `timedOut: null`、`timeoutStatus: "unconfirmed"` 及诊断信息，App 明确显示未确认。退出码为零本身不会清除超时标记，默认超时时长保持不变。

**授权与提问** 页面及 Android 通知与 Web 展示同一份 DSH 待处理请求。授权按钮发送原有的 `allowed-once` 和 `rejected` 结果。授权通知将提示与工具详情一并提供：Shell 详情使用实际工作目录和原始完整命令，其他工具使用原始参数，详情超过 3,500 个 UTF-16 编码单元时明确截断并提示进入 App 查看完整参数。简单问题可用通知选项或直接回复文字处理；复杂问题打开对应的 App 页面。等待、继续和取消由原问题控制器管理，通知投递令牌不会授予额外权限。旧通知或已回答请求不能重复作答，未确认的提交保留草稿且不会自动重发。App 提供系统通知权限与通知类别设置入口。

**后台任务** 展示原版 Agent 队列、待处理请求入口，以及记录的回合和子进程任务结果。取消操作停止当前回合并保留排队输入；移除队列项需要单独确认。停止请求成功后，界面会等待核心确认空闲才结束“正在停止”状态。缺失或尚未核实的历史会明确标注。子进程页面订阅原版任务目录及按字节游标续传的输出流，限制界面保留的输出量，并提供明确的停止请求。离开这两类页面不会取消任务。

**子 Agent** 在原生页面列出会话直接委派的子项，支持继续查看下级目录和分页历史，浏览不会启动或恢复 Agent。读取或控制有会话记录的子项时，使用直属父会话与子会话地址，由原服务校验。一次性子 Agent 和类型仍未知的子项只提供只读历史，外部条目不会获得伪造的会话历史。父会话可用时，可通过原版 `queue` 或 `steer` 操作向可续聊子 Agent 发送文本。原版父级中断操作停止当前回合并保留排队输入。提交结果未确认时，在当前 App 进程内保留草稿和请求标识，刷新与重连只读取状态，不自动重发；待确认草稿不能跨 App 进程终止保留。发送回执表示已接收，不代表工作已完成。

**后台执行** 展示前台服务的真实任务摘要、CPU 唤醒锁状态和系统电池限制，并提供 Android 应用设置入口。可选的 CPU 保护使用有时限、可续期的唤醒锁，仅在核心最新状态表明 Agent 或后台作业正在工作时持有。只有等待回答或排队输入时不会持有；状态过期会释放保护并显示尚未确认。这不能保证进程不被 Android 停止。

**自动化任务** 使用原版任务目录、编辑、删除和投递记录。App 可筛选任务，修改活动任务的名称、指令和时间规则，并返回所属会话。创建入口打开对话，由 Agent 使用现有定时工具创建任务；App 不增加暂停或立即运行操作。编辑时比较原任务记录，发生冲突或结果未确认时保留草稿。投递记录表示提醒已到达会话，不代表模型执行完成。

**聊天加号菜单** 遵循 DSH 的“添加”和“指令”分组及运行时实际指令目录。Android 当前禁用桌面沙箱权限预设，不伪造替代权限菜单。尚未配置凭据时也能创建会话、添加文件及使用不调用模型的指令。文件使用系统文档选择器和原版会话上传收据，上传失败保留所选文件以便重试。此预览尚未启用图片。指令通过原命令服务执行。ZIP 导出使用原版会话日志格式和系统保存选择器。

**对话展示** 按原版消息来源区分用户输入与注入的上下文。上下文和系统提示默认折叠，可展开查看。回复使用 GitHub 风格 Markdown 渲染，支持表格、列表和代码块。列表按需构建可见的对话项目并保留展开状态；流式回复使用原始调用尝试标识，区分重试内容。

**授权文件** 支持单文件、目录、分段 UTF-8 读取及撤销授权。App 与 Agent 共用持久 SAF 授权范围内的字面文本搜索，可选择区分大小写，并限制读取量、遍历范围和执行时间。结果标明跳过的文件与未完成的搜索；不完整结果为空不代表没有匹配。取消操作等待原生搜索实际结束，文档授权不会将 `content://` URI 转成 Shell 路径。

**工具活动**按原始回合和步骤配对调用与结果，包含嵌套 PTC 调用。紧凑行打开可拖动的详情面板，展示记录的命令、独立的 stdout 和 stderr、退出码及超时状态。复制操作保留完整记录值，运行时截断仍明确提示。原行滚出屏幕或分组折叠后，面板继续跟随该调用更新；切换会话或调用离开已加载历史时关闭。同一已知回合的连续调用可以折叠显示，但不合并记录或改变 PTC 归属。缺失结果、失败和中断保持区分，Agent 空闲不代表工具已有结果。长按消息可打开 FlClash 菜单，复制正文，或进入原生页面选择部分文字。

**会话模型** 区分当前选择和待应用草稿，显示明确的勾选标记及模型专属推理选项。空白会话继承原版目录默认值，已保存但暂不可用的模型仍保持可见。App 在编辑前初始化会话，订阅原版模型投影，应用前检查变更，应用后回读服务归一化的结果。失败保留草稿，结果不确定时先核对再重试。原版 `selectModel` API 没有原子比较并交换操作；这些检查可以发现已观察到的冲突，不能阻止检查与写入之间的所有并发覆盖。

**账号与配置** 页面使用原版账号和模型服务。登录在 Android Custom Tab 中打开官方授权页，临时回环监听器仅处理授权回调，不会启用 Web。完成页的 `dsh://open` 链接返回原生账号页，不携带凭据、不改变登录状态；登录结果由原版账号服务确认。登录成功后调用原版默认模型初始化规则；初始化失败保留已登录账号，并提供独立重试。个人资料、余额和通知独立加载，模型／服务商凭据及默认值有原生编辑页面。异步模型错误显示在对应会话中，重连后仍可查看。

**插件管理**使用原版清单、操作和回执。APK 包含锁定版本的 pnpm 与核心包归档，Android 从已提取的原生库目录执行 Node 命令。主机测试覆盖本地安装与共用 Cordis 解析；设备安装、生命周期脚本和第三方兼容性仍需验收。包操作单独计数，不混入 Agent 回合或后台作业，计数涵盖等待锁、应用变更与回滚。维护切换必须先在运行中的核心取得同步预留，才能保存模式或停止进程；存在包操作或状态未知时拒绝切换，预留释放或进程退出前不接受新的包操作。

**凭据引用** 列出当前设置结构声明的引用，以及用户在 App 中明确输入的引用。模型与工具的同名引用共用原版凭据服务。页面只读取配置状态和可写状态，不读取已保存的密钥或账号记录。替换和移除操作在结果未确认时保留请求归属，页面导航和重连不会重放写入。未保存的密钥输入在本次 App 进程内跨页面保留，进程退出后不保留。

**运行设置导入导出** 分为选择操作、导入内容、变更预览、应用结果和导出预览。系统文档选择器读取或保存 JSON。设置使用易读名称及分组折叠行，原始标识和版本保留在详情中。导出只提供保存文件，导入则先展示所选变更再应用。它通过原版设置服务迁移受支持的普通设置。秘密字段与凭据、Web 控制、设备授权、主题、插件拓扑及受保护的 Android 运行设置不在范围内，因此不是完整备份。未知或无效字段会阻止导入，省略的字段保留当前值。每个命名空间使用原版版本检查，多个命名空间可能部分成功。App 逐项显示结果，遇到冲突或写入结果未确认时停止，保留源文本供核对，不自动回滚或重放。高级 JSON 编辑仍然保留。

**诊断** 区分服务启动或故障与账号状态尚未确认。活动订阅诊断仅展示接口名称、投递阶段及已接收序号，不包含请求参数、响应内容和传输标识。复制或刷新这些观察结果不会重试业务操作。诊断页可明确请求重启服务进程，界面等待实际就绪事件后才报告恢复成功。设置页从原生应用元数据读取实际安装版本和构建号，提供加载、失败与重试状态，不使用写死的版本文字。

**启动配置与恢复** 即使 Node 无法启动，也能使用原生通信。进入维护模式会中断当前工作，等待原服务进程退出，并核对残留的应用进程后才允许写入；进程检查不完整时保持只读。App 编辑 Android 与全局的 `cordis.patch.yml`，以及 Android profile 的 `package.json`，不编辑自动生成的根配置。保存会比较原文件哈希，保留原字节或“不存在”状态的私有备份，并记录操作回执。恢复“不存在”的备份会明确移除当前文件。冲突和未知结果保留草稿，不自动重放。保存时验证 UTF-8、大小和清单 JSON 语法；完整配置是否有效，由随后原版 DSH 的实际启动验证。

恢复页面可预览备份、查看私有运行日志末尾的 64 KiB，并隔离当前内嵌运行资源缓存，以便从已安装 APK 重新解包，不会重置会话、凭据或文档授权。实际服务模式与下次启动偏好不同时，会分别显示。维护模式会保留到用户在 App 中明确恢复正常运行。普通插件激活前，Android profile 的配置组合检查会拒绝替换必要宿主条目或开启静态 Web 监听器的用户配置；可执行扩展仍是应用代码，不是受到沙箱隔离的配置。

**私有工作区文件** 通过原生只读页面浏览 App 默认私有目录。目录分页和 UTF-8 文本分页在继续读取前检查文件变动。文件名与字面内容搜索显示跳过项及受限、未完成的结果，不跟随符号链接。此入口不接受任意设备根目录，也不替代 SAF 授权。读取和搜索限制可在 Android 运行时的高级设置中调整。

**工作区与会话** 使用原版工作区注册表及会话控制器完成列表、命名、置顶、归档、恢复、排序和分叉。在默认私有工作区下创建目录与登记工作区是独立操作，界面保留各步骤的结果。新会话采用 DSH 实际返回的标识。普通分叉仍在会话列表中，委派子会话继续使用独立的寻址入口。归档活动会话需要单独确认停止其工作。会话排序仅限同一工作区；修改会话工作目录不改变它不可变的工作区归属。这些原版修改接口没有原子版本比较，App 会保留草稿并报告已观察到的冲突，不能保证阻止所有并发写入。

管理操作的待确认回执和草稿在当前 App 进程内跨页面保留，不能跨进程终止保留。刷新与重连只读取状态，不自动重发结果未知的创建或分叉。主机检查覆盖原版注册表操作及冷恢复、私有文件接口，以及实际 Shell 进程使用的会话目录。原生工作区管理与私有文件页面已通过部分真机验收，具体操作及剩余边界记录在下文。

Shell 在请求授权前解析会话实际工作目录，通知详情与执行使用同一个目录。之后切换目录不会改变已经批准的调用。后台设置页区分 Android 电池接口、临时 CPU 唤醒锁和厂商后台策略；App 无法读取或自动修改厂商策略，并提供手动设置路径。

<a id="interface"></a>
## 界面与主题

对话首页、侧栏和设置使用 Flutter 原生页面。**外观与主题** 将显示模式、配色、配色风格、纯黑模式、玻璃等级、字号与减少动画独立保存在 Android 偏好中，不依赖 Agent 进程。系统的减少动画设置优先生效。标题栏与对话输入框悬浮在全高滚动区域上；内容内边距让首尾项目可以完整露出，同时不截断滚动视口。页面通过 `lib/ui.dart` 组合导入的 FlClash 组件，Material 基础控件只用于实现统一组件样式。

实际玻璃 Shader、背景采样、按压拖拽弹簧、组合按钮、分段选择器、开关、仪表盘卡片、填充输入框、超椭圆形状、字体、配色生成和页面动效来自 [licenses/flclash-source.json](licenses/flclash-source.json) 记录的版本适配。聊天加号菜单使用导入的 FlClash 弹层，从按钮锚点展开并支持按住拖选；在菜单项上释放才选中，取消不执行操作。App 受 [LICENSE](LICENSE) 约束；依赖许可证保留在 `licenses/`。Pocket Harness 显示名称不改变内部包名和应用 ID。

设置详情统一采用单层分组、组外标题和内缩分隔线，说明与原始配置元数据按需展开。侧栏分别展示工作区、置顶会话和最近会话，账号与设置入口固定在底部，搜索按需展开。长按会话使用 FlClash 锚点菜单，提供置顶、重命名、归档、导出和详情操作。这些操作复用原版目录的状态与回执，结果未确认时不会自动重发。

插件设置将安装及当前进度放在顶部，已选用插件包、其余目录和运行时条目分别展示；随应用提供的包、配置依赖与缺失文件保持区分。打开或返回安装页保留草稿和请求标识，不会启动另一轮安装。

## 验证范围

Flutter 测试覆盖草稿保留、主题、悬浮控件、弹层拖选、大字号适配、工具配对、自动化编辑及模型选择恢复。运行设置迁移、任务队列与历史、后台状态与 CPU 保护、对话展示已通过代码检查和针对性的主机回归测试；真机验收仍为部分完成。主机测试还覆盖原版定时操作、Shell 审批结果和共用文件搜索的生命周期。电脑上的冒烟测试让真实 Agent 经过本地模拟模型、Android 工具回执和第二次模型调用；在第二次调用期间关闭 Web 后，任务继续运行。测试也覆盖浏览器认证、连接断开及凭据轮换。这些检查不能替代 Android 上真实服务商与工具调用的验证。

内嵌运行时、官方账号授权及个人资料／余额读取已在关闭 Web 的 ARM64 Android 真机上运行。本机 Web 认证和关闭监听也已在该设备检查。返回链接及账号默认模型初始化已在使用专用协议通道的真机上通过检查。弹层展开、收拢、按住拖选，Flash 与 Pro 双向切换并重新进入页面，以及授权合成文件的 UTF-8 读取和字面搜索，已通过真机检查。

构建 11 已完成使用登录账号的真实模型闭环：合成附件上传并被正确读取，两次 Shell 调用收到原版 `allowed-once` 决策，三个工具结果均成功，回合正常结束。结束并重新启动 App 进程后，同一对话、工具结果及已选 Pro 模型成功恢复，测试会话随后切回 Flash。原版 ZIP 经系统选择器保存后通过 CRC 检查，包含会话日志和逐字节一致的合成附件。这些检查实际使用了设备上的原生文件发布实现。

构建 12 已通过系统选择器保存运行设置 JSON，并重新读取进行导入预览，待应用变更为零。App 在后台时，通知中的原版 `allowed-once` 操作批准了 `sleep 45; echo BACKGROUND_OK`，结果包含 `BACKGROUND_OK` 且退出码为零，但错误地报告了 `timedOut: true`。这确认了命令实际执行，不能证明超时报告正确或后台验收完整通过。针对性的主机回归覆盖迟到截止定时器的修复与显式未确认状态。

构建 13 已安装，设置页显示原生元数据中的实际版本 `0.1.0`、构建号 `13`。原生子 Agent 目录的只读入口与空状态已通过真机检查。展开后的授权通知显示了完整的 `sleep 45; echo BACKGROUND_OK` 命令及实际工作目录，测试人员点击了原版 `allowed-once` 操作。

在测试手机的“智能优化后台运行”耗电策略下，构建 13 的首次任务直到 App 回到前台才返回，结果为退出码零、`timedOut: false`：错误的超时标记已修正，但这次执行没有通过后台验收。

仅将 Pocket Harness 改为“完全允许后台行为”后，同一命令从批准到工具结果耗时 45.060 秒，返回 `BACKGROUND_OK`、退出码零及 `timedOut: false`。期间 App 一直在后台，桌面启动器位于前台；Agent 回合正常结束，前台服务通知回到空闲，设备的 Restored Wake Locks 记录中已没有本应用的唤醒锁。测试手机保留该耗电设置，这可能增加耗电。此结果仅覆盖该设备及设置，不能代表其他厂商的后台策略。

构建 14 在手机上通过了部分原生工作区管理流程：目录显示已同步，合成目录 `pocket14a` 创建后单独登记为工作区，从中开始新对话后打开了服务实际返回的会话。会话的工作目录上下文与详情均指向新目录。置顶显示原服务确认的结果，按钮变为“取消置顶”。归档和恢复也显示了确认结果；本轮没有单独执行取消置顶。最终安装包安装后，ADB 报告构建号为 14；冷启动后侧栏保留了本轮测试会话和之前的 Shell 测试条目，已同步的目录中也保留了 `pocket14a`。最后这次检查没有重新打开会话正文，也未验证完整恢复链路。

私有文件浏览器从根目录进入 `pocket14a`，准确展示了 54 字节合成文件 `acceptance.txt` 的正文。对 `synthetic` 的内容字面搜索命中第二行，App 显示搜索已完成。改名保存、排序、分叉，以及归档活动会话前确认停止的路径仍只有主机测试覆盖，本轮尚未通过真机验收。`pwd` 提示由模型根据上下文作答，没有工具调用，因此本轮不能证明 Shell 已在 Android 的新工作目录中实际执行。

构建 15 已在手机打开重做后的设置分组、导入导出各阶段和侧栏长按菜单。运行设置 JSON 经系统选择器保存后重新选择，15 项设置的导入预览均为零变更，没有提交应用。构建 16 已安装并显示实际构建号；导出预览按真实配置定义区分 API 模型、账号模型、子 Agent 模型选择和 Web 界面设置。未知插件设置保留原标识，不再用关键词猜测通用名称。

在没有运行任务时，构建 16 经显式确认进入维护模式，页面确认旧 Agent 进程退出、配置编辑权限开放。恢复运行先显示等待，随后收到原 DSH 的 `ready` 事件。正常模式下原始配置保存重新禁用。Web 保持关闭，连接手机回环端口 3080 被拒绝；先前合成会话的正文和工作目录详情能够重新打开。本轮未修改原始配置，验证了这台设备的服务替换和维护准入；目录同步、备份写入与恢复、残留进程导致拒绝写入，以及损坏配置恢复仍需真机检查。凭据引用的修改也仍只有主机回归覆盖。本地 Flutter 截图覆盖导入导出的浅色、深色与大字号布局；这些截图及真机截图均不能证明帧率表现。

构建 16 还通过原版通知操作批准了 `sleep 45; echo lockedbackgroundok`，随后手机保持锁屏直至任务完成。记录的结果包含该标记、退出码零和 `timedOut: false`，回合正常结束。但从批准到工具结果耗时 118.527 秒，因此只能证明锁屏期间完成，不能证明按时执行。中途观察到唤醒锁，现有证据不足以确定延迟原因。测试期间 USB 始终连接并充电。

构建 17 已安装，APK 包含原生 Node 命令与 pnpm 资源；设备命令检查分别返回 Node 24.22.0 和 pnpm 11.28.5。App 重新打开了先前的合成会话和插件清单；长按回复弹出复制／文本选择菜单，文本选择页显示对应正文，Shell 详情面板可以拖动展开。这些观察不能证明应用进程内实际安装包或执行生命周期脚本。此后对插件页面布局的调整仅有主机 Widget 测试证据。

真实子 Agent 续聊与中断、自动化、账号待确认恢复路径、锁屏执行的时效稳定性，以及拔线后台运行仍需手机验收。App 全量管理覆盖及限定运行设置之外的配置迁移仍未完成，复杂配置仍使用 JSON 输入。设备截图、诊断日志、个人会话和生成的 APK 是本地文件，不进入 Git。
