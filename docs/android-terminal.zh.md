# Android 会话终端

[English](android-terminal.md) | 中文

## 输入与进程归属

每个终端都归属于嵌入式 Host 中一个仍在运行的会话所有者。离开页面只会分离视图，PTY 继续运行；Host 消失后该 PTY 结束，重新打开页面不会自动创建替代进程。原生辅助进程确认每条输入及尺寸调整后，App 才报告操作已接受。

终端列表允许用户在独立文字页面重命名运行中或已退出的终端。名称归属于对应会话和 PTY，离开页面后仍保留，不会改变进程或工作目录。名称有长度限制，控制字符会被拒绝。Host 终止后 PTY 本身消失，名称也不会在 Host 重启后恢复。

新建终端按钮使用 App 私有存储中的上次 Shell 选择。旁边的选择页探测 Android 固定系统路径中的 `sh`、`mksh` 和 `bash` 是否确实可执行；打开选择页不会创建 PTY。选择 Shell 会保存其 ID 并启动终端，发现失败时可重试。创建时 Host 只核对选中路径，其他候选 Shell 的探测失败不会阻止它启动；原生 PTY 辅助程序也独立限定为这三个固定的 `/system/bin` 路径。系统升级后若上次选择的 Shell 消失，启动会停止，用户可另选一个。终端以 App 的普通 UID 和权限运行；选择 Shell 不是沙箱，也不是通用 Linux 容器。

输入框默认使用**实时输入**。输入法组词留在本地，键盘确认后才按顺序送入 PTY；回车等待尚未确认的文字送达。写入确认后只移除已发送的前缀，保留等待期间输入的新文字。其他控制键要等可见文字送完后才能发送，避免顺序错乱。无法确认送达或已发送前缀被修改时，剩余文字保持可见，自动发送停止；用户需要检查终端后再明确重试。**草稿输入**可按需一次性发送输入框内容，适合粘贴整条命令。若程序启用了括号粘贴模式，草稿文字会被粘贴起止标记包围，发送命令时回车跟在结束标记之后；实时逐字输入仍按原样发送。控制键按钮与支持的实体键发送原始终端字节；屏幕按钮和实体方向键均遵循程序设置的应用光标模式。两种模式随 PTY 保留，离开终端页面再进入时由 Host 屏幕快照恢复。

## 显示与查询响应

Host 将有界的 xterm 网格投影为带样式的字符格，程序设置的 OSC 调色板及光标状态随 PTY 保留。OSC 十六进制颜色的每个通道按位数缩放到 8 位，包括短格式与扩展格式。xterm 的光标位置和设备属性查询响应经由与用户按键相同、需要确认的 PTY 输入通道返回。OSC 4 与 OSC 10–12 颜色查询只对程序先前设置过的颜色作答；未设置的颜色不会被填入虚构的 App 主题颜色。单条自动响应最多 4 KiB，未确认的响应总量最多 32 KiB；超过限制会使终端失败，避免无限积压输入。

程序同时启用 DECSET 1006 和鼠标追踪模式 1000、1002 或 1003 时，Host 会将模式与 PTY 一起保留，终端视图将实体鼠标或触控笔的按下、松开、拖动、移动和滚轮操作编码为 SGR 报告，经确认后的终端输入通道发送。报告使用当前可见网格中从 1 开始的坐标；移动报告遵循程序选定的点击、拖动或全部事件模式。重新打开页面会读取仍在运行的模式。触屏仍用于滚动终端历史。程序仅请求旧式鼠标编码时，不会收到鼠标报告。

这尚未覆盖全部 VT/OSC 行为及 Web 终端控制器能力。旧式鼠标编码、全部终端查询、桌面标签恢复及 Host 终止后的进程恢复仍需继续开发。主机与 Flutter 测试不能证明 Android 真机上的输入法、实体指针、Shell 可用性、PTY 或进程行为。
